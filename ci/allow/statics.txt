rust-modules/gfx/src/gfx.rs	GROUND_PROBE: the top bar's ground sampler. Its heap, `ready: Option<Vec<u8>>`, is allocated only by `read_if_finished` from a `glReadPixels` of the probe's own FBO (`fbo_target`, which needs a live GL context) and dropped by `invalidate`; its `queued: Option<ImageTaps>` holds one `Rc` of the band image's texture from the sampler's call to the frame boundary, where `kick_queued` takes it. Both are touched only on the thread that owns the GL context: `ready` between frames, `queued` from the draw that asks for the copy (`step`, mid-page) to the boundary that takes it (the `Rc` is cloned and dropped on that thread), and no host test can reach an allocation; the tests that touch the probe set its cadence counters under `testlock::serial()` and never read back. Not a frame-loop CPU cache that `thread_local!` would make private: it is GL bookkeeping that belongs with the context

rust-modules/gfx/src/gfx.rs	FIELDST: the exact-2x reduction chain of GL framebuffers behind the dim field. Its `levels` Vec is built and replaced only by `field_lazy_init`, which stores a chain only after every `fbo_target` (`glGenFramebuffers`) in it succeeded, so only the thread that owns the GL context reaches it and no host test can (a host test has no chain: `FieldTicket::for_test`)
