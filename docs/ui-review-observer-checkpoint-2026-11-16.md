# Passive frame observers and single replay authority

## Scope and causal regression

This bounded P2 change starts from source release `e16938b5d3ed80569c494eee2e1f3a76b66b73baca863baf88466e1786df1705` in the isolated review worktree. The prior direct `AppEffect::route` FIFO conversion is unchanged. App child ownership and extension acceptance are separate work; this is not final whole-product acceptance.

The actual `owned_observer_and_command_resources_are_borrowed_sequentially_once` regression was run before implementation with the passive caller expectation changed from zero to two. The repository-pinned toolchain at the tested revision executed the test and failed at `dispatch_return_tests.rs:387`: `left: 0`, `right: 2`. This was a runtime assertion failure, not a compiler failure. `frame_tap` selected `Owned` instead of the explicit caller, suppressing both caller effect observations around a yielded command.

## Source contract

- `rust-modules/ui/src/dispatch.rs`: `Tap` contains passive callbacks only. The six resolution methods belong to `ReplayAuthority`. `FrameObservers::Replay` explicitly grants a single owned recorder both capabilities; `Owned` grants passive observation only. An unknown caller implementing both interfaces is still passed as `dyn Tap`, so cannot answer decisions.
- Every existing passive callback and the terminal `command_done` callback fan out once, owned first and caller second. Callback borrows end before the next authority or resource borrow. `state` memoizes its lazy hash across both observers and repeated reads; two unarmed observers do not walk state. No shared mutable cell, global authority, unsafe alias or resource-executing fanout is introduced.
- `rust-modules/src/app/bridge.rs`: actual `CommandRig` explicitly selects the recorder's `Replay` capability. Result source, captured readiness, native-command admission and resources remain with their existing single product owners. A passive caller never enters those ports. `NoTap` production callers still work. The explicit continuation helper accepts the same passive caller through POST completion.
- `rust-modules/ui/src/dispatch/replay_frame.rs`: test-support direct drivers explicitly borrow their recorder as authority rather than smuggling it through `Tap`. A second owned capability is rejected. This adapter leaves external heads yielded; a direct driver must resume through the same adapter. The erased-Off-recorder tests retain their original Bridge runner instead.
- `rust-modules/src/app/recorder.rs` and `bootstrap/tests.rs`: recorder decision implementation and direct replay tests use the separate interface; passive implementation retains all original observation/codec behavior. Actual AppHost Settings frames check caller input/result/focus/frame callback cardinality alongside owned recording and both replay modes.
- `rust-modules/src/app/run.rs`: actual AppHost Player record/replay test retains real draw and swap-receipt ingress. A non-NoTap caller now survives product PRE and continued POST yield/resume, matches the product's two terminal receipts, and cannot override replay authority or admit a Home command from Player.

## Negative controls and verification boundary

`dispatch/observer_tests.rs` checks every callback, lazy hash count, repeated hash reads, a malicious caller authority trap and second-authority rejection. Terminal-outcome tests reject a duplicate resume without producing another observation. `ci/ui_boundaries.py` and its mutation tests reject dropped owned/caller observations, duplicate forwarding, omitted result callbacks, passive replay methods, a second decision path and uncached hashes. Existing unsupported-native-IO, strict V13, codec and fixture-hash checks are retained without allowance or fixture updates.

The bounded validation commands are UI tests, default app tests, hostsim app tests, shipping `play-uri,play-feed` check, workspace/all-target Clippy with the three existing named condition lints, and both Python boundary suites plus executable guards. They run in WSL Ubuntu-22.04 with `env -i`, the repository-pinned toolchain at the tested revision, Python 3.12, `CARGO_INCREMENTAL=0`, `PYTHONDONTWRITEBYTECODE=1`, and no `GIT_*` environment. Frozen source, HEAD, raw index and staged entries are checked before and after the gate batch. No commit, push, history edit, TV operation or final full make is part of this checkpoint.

The frozen bounded batch passed: UI **1645**, default app **1431**, hostsim **1649**, shipping check, the named Clippy gate, Python boundary tests **29 + 18**, and both executable Python guards. Source, HEAD, raw index and staged entries stayed unchanged throughout. The source-scope audit finds only the observer implementation, its callers/tests/guards and these public documents changed from the released prefix; all changed files use canonical LF. Fixture payloads, fixture hashes, allowance inventories and prior direct associated routing are unchanged. App owner work must precede the final whole-make node.
