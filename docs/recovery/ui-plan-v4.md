# PlxNative UI restructure — specification v4

One owner for every state, event and resource; every rule defined in exactly one section and referenced from everywhere else. Sections are numbered so a rule can be cited as §N.M. This version replaces v3 wholesale; it folds in the owner's review (five mandatory fixes, two focus clarifications, four carried remarks) and the six-angle board review (ownership, determinism/privacy, frame cost, focus/hit engine, migration/gates, library boundary), each finding verified against the tree before adoption.

## 0. Goal and definition of done

**Goal (the owner's words).** The application's behaviour is described by several linked, DETERMINISTIC state machines — session, navigation, screen instances, playback — each with an explicit owner, interacting only through typed events, never by writing another machine's state. Screens are owned INSTANCES; navigation (tabs, page stacks, modal surfaces) is part of the model; time is controlled and real scenarios record and replay; logical state is separate from render resources; standard components carry behaviour; heavy work is scheduled under a bound; the whole app migrates, Settings first, the player included with a special render strategy; ordinary navigation is automatic from components and containers; old paths are deleted and the result proven. "More work" changes the estimate, never the goal.

**Done** (each checkable, §15):
1. `ci/check-statics.sh` at zero: no `static mut` in any screen or engine module; the three main-thread machine globals (`route.rs SESSION`, `player/engine.rs ENGINE`, `ui/press.rs S`) gone; render-cache statics allowlisted by name with a reason.
2. `ci/check-deps.sh` at zero on all three rules: the library (`ui/`) names no application module; a screen names no sibling screen and no store mutator; a store names no UI.
3. One navigation system (`Route`, `Modal`, `Overlay`, `Trail`, `nav.rs` statics, the ladders — absent); one owner of every modal's phase; one focus engine and one hit map, with no per-screen `move_focus`/`pointer_focus`/`top_focus`/`key(sym)` function.
4. `app/run.rs::run` ≤ 200 lines; `plex_run` a ≤ 10-line `extern "C"` shim.
5. A new screen touches its own `screens/<name>.rs`, `screens/registry.rs`, `dev/scenarios.rs` and `tests/manifest.json` and nothing else (proven by `git diff --name-only` on the `about_panel` and `Diagnostics` conversions, §13 phase 10).
6. Every one of the 18 app.rs test modules green in its new home; every gate test of §15 green in all three cargo configurations.
7. All fps scenes at their floors and ceilings with the heartbeat word table unchanged (§15.3), plus the new ramp / cold-open / stall gates, measured panel-ON.
8. The committed replay fixtures (synthetic PMS, §5.6) replay in both modes on the host in `make check`; the same-build determinism claim is proven; cross-target replay is reported as a measured goal (§5.5), not assumed.
9. `doc_claim_auditor` clean against the prose list in §11.

### 2.2 The tree `App` owns (containment, never references; the dispatcher is stepping logic with no state)

```
App
 ├─ Session   auth phase, profile + ProfileScope (the ONE profile generation), server roster facts   → publishes a snapshot (§2.3)
 ├─ Consent   the two telemetry decisions + revision                                                → publishes a snapshot (§2.3)
 ├─ Input     Press machine, key-repeat edge detection, pointer visibility + dpad_mode, hit map (double-buffered), FocusEngine — which holds THE current
 │            FocusKey per input scope and every group's remembered cursor (the only focus state there is; screens keep no copy, §7.3), InputOwner resolution
 ├─ Present   the present gate (DIRTY/WAKE/KEEPALIVE/ENABLED); its only main-thread entrance is Present::note(PresentEvent) (§4.4); ONE atomic door for workers
 ├─ Navigation the container tree (§6): TabContainer → NavStack (one shared) → ModalStack; every Entry/Instance — INCLUDING the entries of a
 │            screen-owned ModalStack (§6.2), which are minted and registered through Navigation on mount; the live/inflight index; input_owner()

 ├─ Player    PlaybackSession (route.rs SESSION) + ForegroundLifecycle + video_plane_bound; engine-facing only
```

Ownership assignments that were double before and are single now: HUD/scrub/held/up_next/overlays belong to `PlayerScreen` (an Instance); the playback session and foreground lifecycle belong to `Player`; key-repeat EDGE detection belongs to `Input` (it emits `Edge::Repeat`), the transport's repeat BEHAVIOUR (`RepeatGate`, `Scrub`) belongs to `PlayerScreen`; the press belongs to `Input`; the modal phase belongs to `ModalStack`; `ProfileScope` belongs to `Session` (a bump emits `Fx::App(AppFx::Emit(Event::Nav(NavEvent::ResetForProfile)))` and one `Fx::App(AppFx::Store(id, StoreCmd::ResetProfile))` per store; nobody else writes it); the poster per-frame quota belongs to `Budget` (§8), spent by `TexCache::prepare` at §3.3 step 9 regardless of surface activity (§10).

### 2.3 Cross-thread snapshots (the rule that replaces "delete every global")

A machine owns a DECISION; when a decision is read from another thread it is PUBLISHED into an immutable snapshot the machine writes on change and workers read freely. `Consent` owns the decisions and publishes into today's `consent::CURRENT`/`REVISION` (so `allows_usage()` stays safe per event on the telemetry/diag threads); `Session` owns the login controller state — today `login_thread` MUTATES `CTL` from the worker (phase, account token, PIN bytes, QR generation; auth.rs:954–1131), which is a cross-thread write: those become addressed results — `Event::Async{addr: Addr{to: Session, req}, payload: AsyncPayload::Sys(..)}`, whose payload `Session::step` parses as its own `LoginProgress{..}` (the §3.1 rule: the requester parses) — applied in `Session::step`, and `CTL` shrinks to a read-only published snapshot (client id, epoch, QR generation) the worker reads; the server registry (`plex/servers.rs`) is an ADAPTER-owned resource whose changes reach the app only as `Event::Session(RosterChanged{roster_gen})`, and replay reconstructs it through the stub adapter. `ci/check-statics.sh` therefore names for deletion only the main-thread globals (`SESSION`, `ENGINE`, press `S`) and gates the WRITERS of a published snapshot (only the owning machine's adapter call may write it).

## 3. The contract

### 3.1 Library types (`ui/machine.rs`), generic over the application

```rust
pub trait Host: 'static {
    type Arg: ScreenArg;                                  // the app's screen argument enum
    type Fx: 'static;                                     // app effects: Store/Net/Disk/Sys/Player/Poster/Emit
    type Msg: 'static;                                    // app payloads: Async results, Store notices, Deliver payloads
    type Elem: Copy + Eq + Hash + 'static;                // ElemKey (interned; never a String)
    type Views<'a>: Copy;                                 // the read side: &BrowseView, &MetadataView, …
    type Init: LogicalState + 'static;                    // the application's initial conditions for a recording header (§5.3); LogicalState is §5.4's trait
}
pub struct ScreenId(u32);   pub struct RequestId(u32);   pub struct EntryId(u32);   pub struct InstanceId(u32);   // library newtypes
pub struct TimerId(u32);    pub struct PressId(u32);     pub struct GroupId(u32);   pub struct PosterKey(u32);    // more library newtypes (PosterKey is NEW, phase 2: posters.rs keys internally today)
pub enum Leave { Deeper, ForGood }                        // why an entry is left (§3.4)
pub enum Chrome { TabBar, None }                          // what shared chrome a ScreenArg wears (today's `Nav::wears_tab_bar` match)
pub enum Handled { Yes, No }
pub trait Machine<H: Host> { type Ev; fn step(&mut self, ev: &Self::Ev, cx: &Cx<'_, H>, fx: &mut Effects<'_, H>) -> Handled; }
pub struct Cx<'a, H: Host> { pub views: H::Views<'a>, pub tick: Tick, pub measure: &'a dyn Measure, pub press: PressRead, pub focus: FocusRead<H::Elem>, pub owner: InputOwner }
pub struct PresentHandle<'p>(&'p mut Present);            // the dispatcher's reborrow of App.present for one step; `note(PresentEvent)` is its one method (§4.4)
pub struct Effects<'p, H: Host> { buf: Vec<Fx<H>>, present: PresentHandle<'p> }   // ONE dispatcher-owned buffer; the dispatcher stamps `from: MachineId` at push
impl<'p, H: Host> Effects<'p, H> { pub fn push(&mut self, fx: Fx<H>); pub fn note(&mut self, ev: PresentEvent); pub fn invalidate(&mut self, why: Provenance) { self.note(PresentEvent::Damage(why)) } }
// `push` and `note` are the two exits; `invalidate` is sugar. `Player` sends `VideoPlane` and the integrators report `Motion` through the same handle
// (`motion::spring(.., t, present: &mut PresentHandle)` — the last argument replaces gfx.rs's global `note_spring`); `TtfMeasure` records a fault in a
// `Cell` the dispatcher reads at the frame tail and notes as `Fault(Fault::Measure)`, because `Measure` is reached through `&Cx`.
pub enum Fx<H: Host> {
    Nav(NavOp<H::Arg>), Mount(EntryId), Unmount(EntryId),  // structural — executed only at NAV COMMIT (§3.3 step 7)
    Deliver(MachineId, Delivery<H>),                       // executed in the drain
    Timer{id: TimerId, after_ms: u32}, CancelTimer(TimerId), Press(PressArm<H::Elem>), Log(LogLine),
    App(H::Fx) }                                           // handed to the application's adapters; damage is NOT a variant (fx.invalidate(), §3.3)
pub enum Delivery<H: Host> { Screen(ScreenEvent<H>), Machine(H::Msg) }
```
`&mut self` + effect sink rather than a pure `(S, E) -> (S, Vec<E>)`: the stores are too large to return by value and a `Vec` per event is heap traffic; purity is enforced by the `Effects` interface (`push` and `note`) being the only exit, `MainThread` living only in the `Player` adapter, and the gates (§15).

Application side — the bundle is DECLARED in `screens/registry.rs` (`AppHost`, `AppFx`, `AppMsg`, `AsyncPayload`, `Event`), because a screen emits `Fx::App(AppFx::…)` and the §2.1 layer rule forbids it naming `app/`; `app/effects.rs` only EXECUTES `AppFx` against the adapters: `enum AppFx { Store(StoreId, StoreCmd), Net(Addr, NetReq), Disk(Addr, DiskReq), Sys(Addr, SysReq /* incl. GoTvHome, ls2 calls */), Player(Addr, PlayerOp), Poster(Addr, PosterReq), Emit(Event) }`; `enum Event { Input(InputEvent<ElemKey>), Lifecycle(Lifecycle), Nav(NavEvent), Async{addr: Addr, payload: AsyncPayload}, Tick(Tick), Timer(TimerId), Player(PlayerEvent), Session(SessionEvent), Consent(ConsentEvent), Store{id: StoreId, gen: u32} }`. The application's `Host::Msg` is `enum AppMsg { Async(AsyncPayload), Store(StoreId, u32 /*gen*/), Session(SessionEvent), Player(PlayerEvent), Cache(PosterReady) }` (`PosterReady` carries the owned decoded image; declared in §10) — the one type a screen receives as `ScreenEvent::Async(req, msg)`/`ScreenEvent::App(msg)` and a store, `Session`, `Player` or `Cache` receives as its `Delivery::Machine`. `AsyncPayload` is GENERIC (`Http{status, blob}`, `Disk{..}`, `Sys{..}`, `Refused`, `Dropped{req}`) and parsed by the requester inside its own `step`, so a new screen adds no variant to it (measurement is synchronous and never an async result, §4.3). `StoreCmd` nests per store (`Browse(BrowseCmd)`, …) so a new `BrowseCmd` moves only Browse's fingerprint (§5.4). There is no `Intent`: `GoTvHome`, `Quit`, `SwitchProfile` are `SysReq`/`SessionEvent`.

### 3.3 The frame — ONE algorithm (`ui/dispatch.rs`; §8 only expands steps 8–10)

1. **`system::ls2_pump()`** — the first of three privileged frame calls, all made by `app/run.rs` (the application's loop, not the generic dispatcher) and allowlisted by name in §15.2; the other two sit at steps 9 and 10. The generic dispatcher (`ui/dispatch.rs`) exposes hooks for them and names no OS function.
2. **Ingest** external events: SDL (through `app/events.rs`), the remote FIFO, lifecycle 0x103–0x106, script producers (`dev/scenarios.rs`).
3. **Adapter results**, delivered by ONE composite key: `(completion_frame, adapter_rank, arrival_index)` — `completion_frame` is the frame the result was observed complete on (recorded, so thread scheduling is irrelevant), `adapter_rank` is one rank per PUMP in §1's loop order (a store with two pumps has two ranks, so the list is a permutation of §1 and nothing is named twice): `auth → pms → browse → search → metadata/season (`detail::update` :10463) → person → play → metadata/detail (`pump_detail` :10571, which drains `metadata::DETAIL_SLOT`) → viewstate → alt_sources → poster`, and `arrival_index` orders results of one adapter within one frame. Pinned by `the_adapter_drain_order_is_the_documented_one` and `two_results_in_one_frame_replay_in_arrival_order`.
4. **One `Tick`**, broadcast containers-before-pages. Nothing else advances time.
5. **Expired timers**, in deadline order then id order.
6. **Drain.** The queue is FIFO; every `Fx` except the structural three executes immediately when popped (`Deliver` steps its target and the target's emissions are appended to the tail); the structural three (`Nav`, `Mount`, `Unmount`) are parked for step 7. The bound on WORK per frame is explicit, in two constants: `MAX_STEPS_PRE = 192` step invocations for this drain and `MAX_STEPS_POST = 64` RESERVED for step 7's post-commit drain (never consumable here), both counted per `Deliver`/`Emit` execution; when the pre-commit count is spent, everything still queued is CARRIED to the next frame's step 6 — nothing is EVER dropped from this queue, because it carries structural ops and addressed requests whose loss would strand `inflight`. (`MAX_ROUNDS = 4` remains as the coarse round counter for diagnostics only.) A `Deliver`/`Emit` chain is therefore bounded per frame by the step count, not by `inflight_cap` (which bounds adapter work); a chain that never drains is a bug made visible: `carried=` and the queue's high-water mark ride the heartbeat, a debug build asserts when `carried` grows for 8 consecutive frames, a release build logs once per growth streak. A single machine emitting more than `MAX_EMIT_PER_STEP = 32` effects in one `step` is a debug assertion.
7. **NAV COMMIT.** Parked `Nav` ops apply (a transition's op at its floor, a cut's op now — today's ~25 `route =` assignments are cuts); `Mount`/`Unmount` execute; the lifecycle events they produce (`Enter`, `WillLeave`, `Unmount`) are delivered through ONE post-commit drain with its own reserved `MAX_STEPS_POST` budget (so a key that opens a page mounts it in the same frame even when step 6 spent its whole budget: `a_key_that_opens_a_page_mounts_in_the_same_frame`). There is ONE commit per frame: a `Nav`/`Mount`/`Unmount` emitted DURING the post-commit drain (e.g. from `Enter`) is parked for the NEXT frame's step 7 (`a_nav_emitted_from_enter_commits_next_frame`), and anything the post-commit drain cannot finish in its budget is carried to the next frame's step 6 ahead of that frame's new work.
8. **Present decision**: `will_present = Present.take(tick) || Budget.has_queued_work()` — `take` (the take-and-clear) runs exactly once, here, and answers `true` unconditionally while the gate's `VideoPlane` input is set (§4.4 — the video plane reaches the gate ONLY through that input, never as a second term here); the RECORDED present bit is `will_present` itself, so a work-forced or video frame that draws is recorded as drawn (§5.3). (`peek` exists for instruments only.)
9. **Prepare** under the §8 budget, only if `will_present`; then — on EVERY frame, presented or not, because the FALSE edge after an unbind may fall on a frame the gate does not present — `opaque_route(Player.video_plane_bound)` (privileged call, the update tail's position today; `Player.video_plane_bound` is the same bit whose changes `Player` sends to the gate as `VideoPlane(bool)`).
10. **Draw** if `will_present` — `clear_opaque_region()` at draw entry (privileged call) — (§8.3), then **tail** (capture, instruments, recorder flush).

## 4. Time, arithmetic, measurement, present gate

### 4.1 Tick and clock
`Tick{ms: u32, dt_us: u32}`; `trait Clock { fn tick(&mut self) -> Tick }` — `SdlClock` (one `SDL_GetTicks` per frame) | `VirtualClock` (replay). Every integrator takes the tick from its event: `motion::spring(…, t)`, `Ramp`, `Phase` (both REPORT motion from inside `advance`, exactly as `gfx::spring` does — the two clock-driven animators that froze in the product, `Xfade` and `Spinner`, are why); `Timer` replaces `up_next`'s deadline, `hud_until`, `refresh_hubs_at`, `script_step_due`; the press arms take `InputEvent::at`; `route.rs`'s `auto_last_switch: Instant` (:176, `.elapsed()` :2793–2794, `Instant::now()` :2801–2804; the file's other `Instant` calls are test-server deadlines) becomes a `Tick`. `idle::dt()` is deleted. Dev oscillators drive from a step counter seeded in the recording header, not wall-clock phase. `Instant`/`SystemTime` stay legal only in adapters, workers and instruments (§15.2 lists the files).

### 4.2 Arithmetic — a VERIFIABLE cross-target goal, not a stated fact
`ui/motion.rs` owns the spring integrators with its own pure-Rust `exp`/`sin_cos` (range-reduced polynomials, pinned by a bit-for-bit table test); everything else in logical state is IEEE `+ − × ÷ √`. Two assumptions are STATED and CHECKED: rustc does not contract into FMA without a flag (grep gate on `fp-contract`/`fast-math`/`+fma`), and the armv7 soft-float routines are correctly rounded for those five operations (a host↔ARM differential table over 4,096 operands: the host half and the `make softfloat-probe` ARM probe target land in phase 2, the ARM half is run and pinned in TV session 3, phase 5b, the first session after the probe exists). The gate covers the full libm surface (`exp|ln|log|powf|powi|cbrt|sin|cos|tan|atan2|hypot|mul_add|sin_cos|as f64`) outside `ui/motion.rs`, shaders and instruments. Same-build determinism is PROMISED (§5.5); cross-target bit-identity is the goal the phase-5 TV fixture measures.

### 4.3 Measurement is a capability, never a free function
`trait Measure { fn width(&self, s: &CStr, sz: i32, bold: bool) -> f32; fn cap_h(&self, sz: i32) -> f32; fn line_h(&self, sz: i32) -> f32 }` with three implementations: `TtfMeasure` (device/sim), `TableMeasure` (replay, from the recording's metrics table), `FixtureMeasure` (host tests). It is SYNCHRONOUS and travels on `Cx`/`DrawFrame`; `Env` stays six scalars; it is not an adapter in the effect sense — no request effect, no async result — but the recorder taps it (below) and replay substitutes it. `text::text_width`/`elide`/`cap_h` are reachable only from `ui/text*` and the three `Measure` impls (gate §15.2). The uninitialised-font case: `TtfMeasure` panics in a debug build; in a release build it returns the font's average advance × chars, sets `Present::note(PresentEvent::Fault(Fault::Measure))`, and the tail logs the fault once — never a silent `0.0`. Every measurement the recording machine performs — including elision's prefix probes and wrap's per-word probes — is captured at the `text::` boundary as `metrics{key(text, sz, bold): (w, h)}` (a side table, not an event), and a table miss on replay is a hard failure. Layout may not derive any input from a decoded texture's dimensions (the `hero_logo` band-height rule, stated once here and gated).

### 4.4 The present gate has an owner
`Present` is an `App` field with ONE typed entrance on the main thread: `Present::note(PresentEvent)` (reached through `PresentHandle`, §3.1) where `PresentEvent::{Damage(Provenance), Motion, VideoPlane(bool), Fault(Fault)}`, `Provenance::{Landing(MachineId), Resource(ResourceKind), Timer(TimerId), Input, Lifecycle, Nav}` (recorded, so a replay diff can say WHY a frame presented) and `Fault::{Measure}` — `fx.invalidate(provenance)` (§3.3) is `Damage`, the integrators' `note_spring`/`note_jump` are `Motion`, `Player` sends `VideoPlane` on bind/unbind (it is an INPUT to the gate; the gate's state has no other writer). Workers get exactly ONE documented atomic door — `present::wake_from_worker()` — used by poster completion and the lab uploader; nothing else may touch the atomics (gate). `peek(tick)` is side-effect-free; `take(tick)` runs once per frame in §3.3 step 8. `MotionScope` is structural: `ModalStack::step` opens one per surface and the page steps in its own, so a modal's foreground springs never re-take the host snapshot. The gate's per-frame verdict is RECORDED (one bit per frame) because the hit map is the last DRAWN frame's (§7.6).

## 5. Addressing, landings, recording, replay, privacy

### 5.1 Identity
`EntryId` (declared in §3.1) is minted whenever an `Entry` is CREATED — by `Push`, `Root`/`SelectTab`, `Replace` or `Present` (a modal surface is an entry, §6.2) — stable for the entry's lifetime, survives body eviction, and is the identity in `ReturnState`, `FocusKey`, supersede tests and the player's origin. `InstanceId` (§3.1) is minted at MOUNT, never reused, is the addressee of async work, and changes on remount.
```rust

pub struct Addr { to: MachineId, req: RequestId }
```
Supersede-by-identity compares `EntryId` (two Detail entries share a `ScreenId`; a CAP-evicted entry has no body to ask). The player's origin is `EntryId` + `Descriptor` so `a_detail_return_names_the_item_that_was_mounted` (app.rs:12081) ports unchanged. `Descriptor = (ScreenArg, ReturnState)`; reuse-vs-remount compares `ScreenArg::same_instance`.

### 5.2 Landing — a bounded per-addressee QUEUE with backpressure
`Landing<K, V>{q: Mutex<VecDeque<(Addr, K, V)>>, cap}` — interior mutability because `put` is called from workers and `take_for` from the main thread. `put` returns `Err(Full)`; the WORKER-SIDE adapter handles it by pushing `(addr, Dropped{req})` into the landing's separate `control` lane, which can never be full because at most one control record exists per in-flight request and `inflight_cap` bounds those — so the addressee always receives exactly one event per request and nothing strands (the owner's finding); the NEWEST data result is what is dropped (re-requestable; page 1 of a listing is not reconstructible). every record in either lane carries one per-landing SEQUENCE number assigned at `put`, and `take_for(&self, is_deliverable: &dyn Fn(&Addr) -> bool, want: &dyn Fn(&K) -> bool, out: &mut Vec<_>)` merges the two lanes by that sequence (so a `Dropped` never overtakes a data result that arrived before it) into a dispatcher-owned buffer; `Navigation` is the sole owner of the live/inflight index behind `is_deliverable`. `K` carries identity (`(ServerId, RatingKey)` for detail — closing metadata.rs:2021's gap) and the `ProfileScope`. Admission control: a store refuses to spawn beyond `inflight_cap` per addressee and answers `Refused` immediately. Per-addressee drop counters are hashed state. **A store's `step` is O(result size)**: library-sized structures (browse's `items.resize_with(total)`, browse/mod.rs:2563) are built in the worker or kept chunked, never allocated on the main thread in the drain.

### 5.3 The recorder (`ui/rec.rs` writer behind `devtriggers`; the `LogicalState` trait unconditional)
Armed by `plxnative-rec[=blobs]` (in `dev::DIAG`, as is `plxnative-recplay=<dir>`, the replay trigger — a NEW name, because `plxnative-replay[=N]` already exists as the non-DIAG EOS replay counter, app.rs:2849); a stable package carries no recorder artefacts (`ci/check-package.py`). Buffered: one `write` per frame at most, fd opened once, NO `scrub_local` on the hot path (the directory is private, §5.6); the logical-state hash is INCREMENTAL — each machine keeps a dirty flag and its own sub-hash, a settled frame re-hashes nothing. `rec=<µs>` rides the heartbeat and an armed recorder DISQUALIFIES a run's `fps=`/`worstframe=`, exactly as the profiler triggers do. Storage: hard byte cap, refuse to arm below a free-space floor, blob capture opt-in; **settled 2026-09-06 (TV session 1): the runtime root is a RAM-backed tmpfs (824 MB, on a 1.65 GB set with ~440 MB available), so a recording competes with the app for memory — the hard byte cap is 64 MB and segment rotation flushes to the app's install directory (`/media/developer`, rw under the devmode jail) rather than staying in `/tmp`;** directory 0700, files 0600. Format: JSONL envelope + content-addressed blobs, segment rotation at 2 MiB, gzip OR identity per segment (named in `manifest.json`; `zlib` ungated behind `devtriggers`). Records per frame `f`: `tick{ms, dt_us}` EVERY frame; `present{bit}`; `in{…, hit, resolved_focus}`; `eff{from, e, addr}`; `async{addr, payload|blob}`; `metrics` (§4.3); `life`, `timer`; `st{hash}` on every event frame. Header: `schema`, `state_fp`, build, features, triggers armed, `init: H::Init` (the APPLICATION's initial conditions — session, servers, consent, favourites, route, rng seed, oscillator seed — produced by `App::snapshot_init()` and consumed by `App::from_init()`; the library `rec` sees it only as a `LogicalState` value), `clock{start}`. **A recording starts ONLY at a controlled boot**: `plxnative-rec` is read at boot, `snapshot_init()` runs at frame 0 immediately after `App::from_init()` and BEFORE any adapter has spawned work, armed a timer or received an event, so the header is a complete initial condition with empty queues, no timers and no inflight requests by construction; arming mid-session is refused with a logged reason, and a full mid-session checkpoint (queues, timers, requests, landings) is NOT promised in this plan. Dev flags reach machines only through `Sys` effects, so a live-read trigger (`failtest`, `testpat`) is a recorded adapter result, and replay answers `dev::flag/read` from the header, never the filesystem.

### 5.4 Canonical state and versioning
`trait LogicalState { fn write(&self, w: &mut Canon); fn probe(&self, out: &mut String) }` — `Canon` is a hand-written encoder (floats as `to_bits`, collections as explicitly ordered sequences, enums as explicit discriminants; NaN/Inf distinct); no JSON is hashed and a `HashMap` in logical state is rejected by the census. `state_fp` is a SHAPE fingerprint from the exhaustive census `match` over field names and types (not a value hash), computed per store and per screen so a new `BrowseCmd` re-fingerprints Browse only. A prepare pass may not change the hash (`prepare_does_not_change_the_logical_state_hash`, `#[cfg(all(debug_assertions, feature = "hostsim"))]`).

### 5.5 The promise, stated honestly
A replay is a REGRESSION ASSERTION pinned to the build lineage that recorded it. Promised: a scenario recorded from initial conditions `I` on build `B` replays on `B` (same target) to a bit-identical `st` and `eff` stream. Goal, measured: the same across host and ARM32 for recordings whose measurements come from the metrics table (the phase-5 TV fixture; if it diverges, the fixture is target-scoped and the divergence named — the promise is not widened). Not promised: loading across a `schema`/`state_fp` change (refused, both pairs printed), replay from arbitrary state, pixels, fps, timing, SDL events the queue dropped before recording. Two modes over every fixture: `--targets` (phase 2) feeds each input with its recorded resolution (`hit`, `resolved_focus`) and grades the application's machines; `--resolve` (phase 3b, when the engine and hit map exist) feeds raw directions/coordinates, rebuilds layout through `TableMeasure` and the recorded `present` bits, runs the engine and the hit map for real for every page whose `FocusSource`/`HitSource` is `Engine` (a `LegacyPage`'s inputs are replayed by target), reports EVERY mismatch as its own line, and CONTINUES from the recorded resolution (so one weighting change is a list of pointwise diffs, not an avalanche). `--rebaseline` is allowed only with a divergence record in the fixture (first diverging frame, preceding event, both fingerprints) that CI verifies. An ANCHOR fixture is one whose `manifest.json` carries `"anchor": true`; `--rebaseline` refuses it outright, and every fixture-PRODUCING phase (2 and each phase from 5b on that records one — phases 0 and 1 produce none) marks at least one of its fixtures anchor. `--resolve` divergence reports are also the per-screen ADOPTION ARTIFACT (§13): every screen that replaces its ladder must name each divergence as an intended change or fix it.

### 5.6 Privacy for a PUBLIC repository (each rule once)
1. Recordings against a real server never leave the machine that took them. `plxnative-rec/` is in `.gitignore`; `outbound-guard.py` gains `PRIVATE_DIRS` (realpath prefix in `named_private_paths`, descendants refused in `payload_parts`) AND a CONTENT rule refusing any outbound payload carrying the envelope grammar (`{"f":`, `"st":`, `blobs/`) — with ONE exception the hook computes itself: a file under `tests/fixtures/replay/` whose every string value passes the synthetic-alphabet verifier (rule 2) may be committed and pushed; the divergence printer's default is `--safe` (frame indices, event kinds, hashes; never string payloads); `lab/` never uploads the directory (a `PRIVATE` marker).
2. Committed fixtures are SYNTHETIC FROM THE START: `tests/mock_pms.py` (new; built from `docs/plex-openapi.json` and `plex/models.rs`) serves a generated library with names from a closed alphabet (`^s[0-9a-f]{8}$` plus enumerated protocol constants) to the simulator, and every committed fixture is recorded against it. No household byte enters the pipeline, so the "synthesis preserves parse/meaning/metrics" problem does not arise. `tests/test_harness.py` checks every string value in a committed fixture against the ALLOWLIST alphabet (a denylist for "title-shaped" is undecidable — `scrub.rs`'s own conclusion).
3. The TV-recorded cross-target fixture is taken against the same mock PMS reached over the LAN (the television talks to the dev Mac already for `serve_fixtures.py`).

## 7. Focus and pointer — one engine, owned by `Input` (`ui/focus.rs`, `ui/hit.rs`)

### 7.1 The container query protocol (complete, never materialised)

`Seat` is the FOCUS-ENTRY policy; `Enter` (§6.1) is the LIFECYCLE event — two names for two things.
Blanket impls: `CardRow`, `TableView`, `TabStrip`, `Grid`, `DocumentReader`, `MasterDetail` implement `Focusable` over their own data; a screen that is `Composed` gets `Focusable` AND the draw skeleton by blanket impl, and the parts it is composed of must be able to DRAW, which `&dyn Focusable` cannot — so: `pub trait Part<H: Host>: Focusable<H> { fn prepare(&mut self, b: &mut Budget, cx: &Cx<'_, H>); fn draw(&mut self, f: &mut DrawFrame<'_, H>, rect: Rect); }` (implemented by `CardRow`, `TableView`, `TabStrip`, `Grid`, `DocumentReader`, `Header`, `MasterDetail`); `pub trait Composed<H: Host> { fn layout(&self, cx: &Cx<'_, H>) -> Vec<(PartId, Rect)>; fn part(&self, id: PartId) -> &dyn Part<H>; fn part_mut(&mut self, id: PartId) -> &mut dyn Part<H>; }` with `PartId(u32)`. The blanket `Focusable` concatenates `groups`/`neighbour`/`place`/`reconcile`/`seat` over `layout()` in order; the blanket `prepare`/`draw` iterate `layout()` and call `part_mut(id)` for each — the only `&mut` access, and it is to a RENDER half; logical state stays behind `step`. There is no separate `Layout` trait — geometry IS `Focusable::place` — this is what makes "assemble a screen from components" an API rather than a convention. A `Free` group is the only kind that scans (`debug_assert!(len <= 64)`). A materialised `FocusTree` exists ONLY as a test adapter for the golden tables. The tree is derived from the screen's PUBLISHED state (what `place` and `draw` read — Library's `may_publish_shelves` rule survives as a named `Focusable` input), never from raw store state. `place(.., At::SpringTarget)` serves focus movement; `At::Drawn` serves the hit map.

### 7.2 Identity
`FocusKey{entry: EntryId, elem: ElemKey}`. `ElemKey` (interned `u32`, app-defined per screen) names a CONTROL, never its face (`Ctl(HeroCtl::WatchToggle)`, not `MarkWatched`). A repeated element is EXACTLY ONE of `Elem::Item(ItemKey)` (a landed item) or `Elem::Slot{group, index}` (a position with no item yet), and equality is STRICT — two keys are equal iff their variants and payloads are equal; there is no item-first/slot-second fallback. The `Slot → Item` promotion after a landing is an explicit `reconcile` answer (§7.3 step 6): the owner's `reconcile(want = Slot{g, i})` returns `Item(k)` for the item that now fills the slot, the engine delivers `FocusMoved{by: Reconcile}`, and the remembered cursor is rewritten; a reorder is the same path in the other direction (`reconcile(Item(k))` returns `Item(k)` at its new position, so focus follows the item). Hit map and focus engine use the same key.

### 7.3 Movement
1. A direction key goes FIRST to the input owner's `step` (`ScreenEvent::Input(Key)`); `Handled::Yes` ends it (a text field's caret, the scrubber, a slider, the HUD's transport, hero paging, "UP hides the HUD"). This is the ONLY way a direction is consumed or turned into an action; `Handled::Yes` arms on direction keys are the greppable exceptions and each carries a reason.
2. Otherwise the engine asks the current group's `neighbour`: inside a `Row` along its axis (wrap per spec), a `Column` the inverse, a `Grid` both with row/column memory and holes skipped along the direction of travel with column memory preserved, `Document` scrolls inside and leaves only at its ends, `Free` by geometry.
3. At a group edge, a declared `Link{from, dir, to}` wins; else the group's `EdgeRule` for that side: `Stop`, `Screen`, `Nav`, or `Geometric` (the default) — a search for the destination group — nearest by axis distance weighted 3:1 against orthogonal offset from the current element's placed rect over every group's extent, EXCLUDING groups whose `reachable` mask omits that axis (the Library rail is horizontal-only).
4. Landing in the destination group by its `Seat` policy — named cases, never one heuristic: **`Nearest`** = `card_row::column_near_x`'s contract verbatim (project the source centre onto the destination lattice; on a tie the element whose index equals the source's, else the lower index — never tree/direction order, which ratchets; test `bouncing_between_two_rows_is_stable` relocated onto the engine); **`Remembered`** = the group's last focused element, UNCONDITIONAL and followed by a reveal (route_screen rules 2/3, detail's `saved_col`, Library's saved view, Search's seat); `RememberedNear{rows}` is the separately named variant for a group that should not chase a cursor far away, adopted per group and listed in §12; `Projected` = a data projection through the container's `seat()` (the rail↔grid door: `letter_of(focus_idx())`); `First`.
5. **The engine owns THE focus state** — the current `FocusKey` per input scope and every group's remembered cursor — and it is `Input`'s logical state (hashed, restored, recorded). It emits `Deliver(owner, FocusMoved{from, to, by})`; the OWNER's `step` is the only place a screen or container mutates in response: it scrolls the target into view (`CardRow::reveal`, `Column::visible_range` — the container's own springs), publishes what the new focus implies, and reads focus thereafter from `cx.focus` (no screen keeps a focus copy; `SettingsSurface`, `MasterDetail` and the others hold none). BACK/restore is `Enter::Restored` → `ReturnState.focus` → `reconcile` → `FocusMoved{by: Restore}` → the owner reveals: restore with scroll, a different path from shelf-to-shelf, by construction.
6. After every store landing (`StoreChanged`) and before draw the engine asks the owner's PURE `reconcile(want)` and, if the answer differs, delivers `FocusMoved{by: Reconcile}` (the three-step ladders `shelf_focus_survives`, `sync_readout_focus`, `spot_landing`, `standin_left_the_ring` become container impls); the engine's own fallback (group policy → first) is the last resort, logged once.
7. Scope: the engine reads the `InputOwner`'s groups only — a modal traps focus; the television keyboard is `InputOwner::System(Keyboard)`, under which Search's field consumes LEFT/RIGHT and text arrives as `Text`; the strip is the container's group (§6.2). `Wheel` is a SCROLL delivered to the container (focus unchanged).

### 7.4 Elements, presses, activation
`ElemKind::{Card, Control, Bare}` on the group's element descriptor: `Card` arms a holdable press, `Control` a non-holdable one, `Bare` delivers `Activate` on the DOWN edge and never arms (person header, search field, recents). `Fx::Press(PressArm{key, from: PressFrom::{Key, Pointer}, holdable})`; `Input` steps the press on `Tick`/`Edge::Repeat`/`Up`, resolves dropped key-ups (`LOST_MS`, `MAX_HOLD_MS`), cancels on navigation, owner change or a `Pointer` press whose `hit` leaves its arm; at `LONG_MS` it delivers `PressHold(id)` — `Handled::Yes` cancels the press (the item menu opened), `Handled::No` latches it non-committing; on release it delivers `PressCommit(id)` to the arming owner only. `DrawFrame.press` carries `scale()`/`is_long()` for the renderer.

### 7.5 Pointer policies (data on the stop, gates in `Input`)
`Stop{key, rect, rest_rect, clip, hover: Focus|Ignore|OnlyIfFocused, activate: Press(kind)|Immediate|Direct}` — the fly-away guard is `OnlyIfFocused`, the rail letter is `Direct` (jump without OK), a dead-space click parks nothing and arms nothing. `Input` gates before `top_at`: `dpad_mode` (hover suppressed until the pointer travels 120 px after D-pad use) and the fading-surface alpha threshold. `Drag` drives the scrubber with no hover and no click. Hover parks focus THROUGH the engine (`pointer_to(key)`), so hover and D-pad land the same way.

### 7.6 The hit map
Registered by the draw: `DrawFrame::stop(...)` records `rect * cascade ∩ clip` in screen space with insertion index (painter's order IS z; no separate z). To make that true the painter gains what it lacks: `Painter{dx, dy, a, rgb, scale, clip: Rect, sink: Option<&HitSink>}` stays `Copy` (`HitSink` is the `Input`-owned back map's `RefCell<Vec<Stop>>` — `DrawFrame::stop` is the only writer); `clip(r)` is a VALUE on the cascade (scissor set at primitive time; RAII on `DrawFrame`, replacing the bare global `clip`/`clip_clear`); `scale(s)` carries the focus pop so a popped tile registers its popped rect; `View::draw` takes `Painter<'a>`. `Placed.rect` is what was painted (pop and press dip folded in — the pointer's target); `rest_rect` is the settled magnified rect (what an `Opener` anchors to and `reveal` bounds against). The map is `Input`-owned and DOUBLE-BUFFERED: the draw fills the back map, the swap happens only on a PRESENTED frame, a non-drawn frame resolves against the previous map (`a_click_on_an_idle_frame_resolves_against_the_last_presented_map`); the blur SOURCE pass registers nothing and mutates no render cache (`DrawFrame.pass`). Resolution: `top_at(x, y)` over the input owner's map; miss → `ModalStack::on_miss`. A `LegacyPage` declares `HitSource::Legacy` and `FocusSource::Legacy`: for it the map, the engine and `on_miss` are INERT and the old ladders remain the single writer until that screen's phase.

## 8. The frame scheduler (`ui/frame.rs`) — expands §3.3 steps 8–10

### 8.1 Budget = admission control, not sampling
`Budget` lands in TWO steps: phase 2 ships the MINIMAL type — the struct, `take(class)` with the clock-before-every-take shape below, one `Class` (`Poster`, quota 3/frame) and nothing else — because §2.2 makes it the owner of the poster quota and §3.3 step 8 reads `has_queued_work()` from it, and both exist from phase 2; phase 11 adds the remaining classes, their pinned `worst_us`, the solo-frame rule and the prewarm occupancy bound. `PREPARE_MAX_US = 2000` (≈25 % of the measured ~7.8 ms discretionary headroom on a Home frame). Every `Work` item declares a `Class` with a device-measured `worst_us` pinned by a test; `Budget::take(class)` reads the clock BEFORE EVERY take (one `SDL_GetPerformanceCounter`) and admits only if `now + worst_us <= frame_start + PREPARE_MAX_US`. A class whose `worst_us > PREPARE_MAX_US` is not prepare work: it is split or moved to a worker (poster decode already is; the GL upload + `warm_tex` pair, ~6 ms, becomes its own class run at most once per frame on a SOLO frame with the ceiling raised to 8 000 µs and `budget solo=<class>` logged). Forward progress: one item per frame for classes that fit. Text prewarm is bounded by cache OCCUPANCY (refuse when `live_this_frame + prewarmed > TCACHE − 32`; never evict an entry touched within 8 frames), graded on `cold-open` and `modal-ramp` plus an `evicted-while-hot` heartbeat counter. (Who spends the `Poster` quota is §2.2's ownership line.)

### 8.2 Absent-resource draw rule
When `prepare` declined, `draw` still produces the element at its FINAL geometry: it may not allocate, upload, rasterise or `dlopen`; the placeholder occupies exactly `place()`'s rect so the hit map, the focus groups and every layout downstream are identical with and without it; it registers its stop and key as if present; the resource is requested once and its arrival is one `fx.invalidate(provenance)`; an animated placeholder reports motion, a static one does not.

### 8.3 Activity table and draw phases
Active surfaces (receive `Tick`, prepare, draw): the input owner; Live hosts; Cached hosts owing a capture; the page unless Replaced. A Cached host below the owner does not prepare, receives `Tick` per `HostUpdate`, draws as a quad; Replaced receives nothing; Closing steps unconditionally; "update" in this document means receiving `Tick` in §3.3 step 4 — there is no separate update phase; a `NavStack` entry below the top updates only mid-transition and draws only under `RoutePush`. `prepare` runs only on a frame that WILL present, or on a frame with queued work that is then forced to present; it is timed unconditionally (`worstprep=`), so a settled screen never runs untimed work at the loop rate. Render residency is checked over the WHOLE frame composition, not the page pair alone: the frame plan's `RenderSet` lists every `ScreenRender` alive this frame — the top page, the page below only under `RoutePush`, every Active surface (a Live host, each Opening/Open/Closing panel, an alert) — and asserts (debug) and logs (release, once per breach) that (a) pages hold at most 2 renders, (b) each surface holds at most one, (c) the SUM of their backing-texture bytes plus the single `FrameCache` stays under `RENDER_BYTES_MAX` (set in phase 11 from the 160 MB `requiredMemory` measurement; a placeholder 48 MB until then), and a Cached host holds NO render of its own (it is a quad from the one shared `FrameCache`, never a second full-viewport texture); `drop_render` on `Cover` under `PageDip`; under `RoutePush` the covered entry keeps its render while it is one of the two live renders (it is drawn mid-transition), and drops it on `Unmount` or when a third render is needed; `CAP` (§6.1) counts entries, not renders. `warm_tex` runs inside the presented frame's GL scope after `glViewport`. Draw phases: `host::begin_frame` + glass owners prepare → page pass (RAII, both passes, scrims INSIDE by `ModalStack::draw_scrims`) → surfaces bottom-to-top → instruments. Cache rules unchanged: `popover::host` stages, glass `DEFAULT_DYNAMIC_PERIOD` 1, `RouteGround` latches once.

### 8.4 Instruments (the timer origin and the eight phases land on the LEGACY loop in phase 0; phase 2 moves them into `Instruments` unchanged and adds `coldopen`, `carried=`, `rec=`, `allocs=`)
The frame timer's origin moves to the TOP of the iteration; `Instruments::mark` stamps eight phases over §3.3's ten steps — `ingest` = steps 1–2 (`ls2_pump` is charged to ingest), `results` = 3, `tick_drain` = 4–6, `navcommit` = 7, `prepare` = 8–9 (the present decision is a read and is charged to prepare), `draw` = step 10's draw, `capture` = step 10's tail, `swap` = the `SDL_GL_SwapWindow` that closes the iteration and `FRAMEDROP` prints all eight; `worstframe=` covers the whole iteration; `worstprep=` is ungated by present; `coldopen screen=<name> ms=<n> prepared=<bool>` once per mount; `carried=`, `dropped=`, `rec=`, `allocs=` (hostsim) on the heartbeat. `cold-open` is graded from `FRAMEDROP` in phase 0 and re-based on `coldopen` in phase 11.

- `testlock::serial()` guards go in the commit that deletes a module's last static.
