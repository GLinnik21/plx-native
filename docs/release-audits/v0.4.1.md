## Device test evidence

| | |
|---|---|
| television | LG 49SM9000PLA, platform release 4.10.2 (LG markets this generation as webOS 4.5) |
| server | a live Plex Media Server on the maintainer's own network |
| suite | `./tests/run.py` — the published note states a 21-case suite against a live server before every release |
| by hand | **three Dolby Vision files played and the panel's own report read for each**: a Profile 5 film and a Profile 8 film both move the set into its Dolby Vision picture mode; a Profile 7 film is refused for direct play and the panel lands on HDR10 |
| by hand | the remote's key codes were settled by two independent readings — LG's own key table inside the television's copy of SDL, and 336 real presses captured from the set |

**What is not established.** All three findings are one television. The transport keys are bound from that set's table and LG's documentation says the Magic Remote has no transport keys at all, so the remotes that could actually answer are ones this project does not own.

## External compatibility reports known at release time

Unchanged from v0.4.0: @mariotaku's [issue #22](https://github.com/GLinnik21/plx-native/issues/22) of 2026-08-11, on an LG 65UP7560AUD at platform release 6.5.2, running v0.2.1. Nothing new arrived in the six and a half hours between v0.4.0 and this release.

## Compatibility tiers, and what moved

Nothing moved. The four tiers are v0.3.0's, unchanged.

**One claim inside a tier got stronger, and it is not a tier move.** v0.4.0 declared Dolby Vision and refused to claim the set acted on it. This release watched the panel act on it — three files, three states the television reports for itself. That is still the same one television in the same tier; it says nothing about any other set, which the note states.

## Known issues at release, with provenance

- **Text outside Latin, Greek and Cyrillic draws as empty boxes** — Chinese, Japanese, Korean, Arabic, Hebrew, Thai, in titles and subtitles alike. The music notes fixed here were one instance; the general case needs a second font and is not done.
- **Plex Relay, servers requiring secure connections, and servers reached by hostname or IPv6.** Structural.
- **10-bit decoding is still asserted rather than probed.**
- **Dolby Vision Profile 7 is refused** and plays as HDR10; whether any set other than the one tested enters Dolby Vision mode is unconfirmed.
- **On webOS 5 and newer, seeking reloads the stream** rather than moving within it.

## Deliberately not done

**`requiredMemory` moved from 60 MB to 160 against a measured peak of about 150 MiB, and the note discloses the old number rather than quietly correcting it.** 60 was worse than declaring nothing: webOS substitutes 120 MB for an app that declares none, so the old figure asked the television for *less* room than silence would have.

**No transport-button row was added to the player.** The keys work; the on-screen read-out is a state mark beside the clock, not a row of buttons, and the direction is read from where the playhead is going rather than from which key was pressed.
