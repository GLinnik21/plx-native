# Release audit — v0.10.0

The evidence behind [the v0.10.0 release note](https://github.com/GLinnik21/plx-native/blob/main/docs/release-notes/v0.10.0.md). Written for a webosbrew reviewer, a contributor auditing an old release, and us in a year. The section at the bottom is generated from the artifact that was published; everything above it was written by a person before the release ran.

**Written ahead of the release, from the repository alone.** This authored half was drafted against `origin/main` at `f8f6dbb75` (273 commits after the `v0.9.0` tag, cut 2026-10-23) by a drafting agent that did not touch a television, build a package or run a suite. Nothing below was measured for this release: it records what the repository's own pull requests, issues and discussions say, with their dates, and it says where they say nothing. The release run's own gates produce the generated half.

**Revised for the second release candidate.** The first candidate (the tag `rc/v0.10.0-rc.1`, the commit `release: 0.10.0`) was cut from `origin/main` after the first draft above. ## Known issues at release, with provenance

- **Direct play hangs on some webOS 5 and newer sets.** Tracked in [issue #1259](https://github.com/GLinnik21/plx-native/issues/1259), which groups #1096, #954 and #1166 and says the causes are not confirmed to be the same. [Pull request #1133](https://github.com/GLinnik21/plx-native/pull/1133), which preserves baseline audio codecs and sizes converted Opus, is named there as the candidate fix for #1096 and is in this release; no confirmation from that set is recorded. [Issue #1166](https://github.com/GLinnik21/plx-native/issues/1166) is closed after [#1263](https://github.com/GLinnik21/plx-native/pull/1263) (the Dolby Vision CRA case) and was reopened once in between; the note lists only the open ones.
- **Not confirmed on a television in the second candidate.** The Library symptoms behind [#1335](https://github.com/GLinnik21/plx-native/pull/1335) item 9: focus seats on the first tile after opening onto Collections or Recommended (a change with a host test that failed before it), and the flash of the old layout on Back to the grid, which did not reproduce in the host rigs and was left unchanged. The note says both are unseen on a television.
- **The managed profile's Plex Pass** is read from the Home administrator's feature list by the owner's decision of 2026-11-11 ([#1335](https://github.com/GLinnik21/plx-native/pull/1335), `docs/pms-api.md`). No real managed account's answers were observed; the policy is not a measurement. A full (non-managed) Home member also takes the administrator's Pass, because the household roster has no flag to tell the two apart.
- **Yellow subtitles recolour every pure-white style in a styled script,** so signs and typesetting drawn in white turn yellow too: a known cost of treating white as the default ink, reversing [#1342](https://github.com/GLinnik21/plx-native/pull/1342)'s "authored ASS is never recoloured" for those styles. A karaoke secondary color is recoloured only when it is itself pure white.
- **Previous from a show's first episode** may open a season 0 special if the server lists specials first in the show's queue; [#1349](https://github.com/GLinnik21/plx-native/pull/1349) did not determine the order, and the note does not mention it. A server that does not select the requested episode in a show-built queue gets the old episode-only queue, where Previous stays dimmed on a fresh play.
- **The subtitle timing offset has no minus direction** ([issue #1284](https://github.com/GLinnik21/plx-native/issues/1284), open).
- **webOS 3.x** is outside the supported range; [issue #862](https://github.com/GLinnik21/plx-native/issues/862) is open and the note does not claim 3.x starts on this package.
- **The k5lp, k3lp and k6hp chip issues** ([#74](https://github.com/GLinnik21/plx-native/issues/74) and [#174](https://github.com/GLinnik21/plx-native/issues/174)) are closed (#174 as not planned, since every event came from 0.6.6 and none from 0.7.0 or later); the note keeps them as known issues because nothing proves them gone.
- **Crash reports.** [Issue #289](https://github.com/GLinnik21/plx-native/issues/289) (native crash reports with no frames on the crashed thread) is open. [Commit `959440fae`](https://github.com/GLinnik21/plx-native/commit/959440fae) ends the process without returning into libc `exit()` to stop the libcrypto lock crash behind Sentry PLX-NATIVE-P cluster A (28 of 43 events, 19 on 0.9.0, per the commit); the remaining events of that issue ([#1115](https://github.com/GLinnik21/plx-native/issues/1115)) are cause-undetermined, and no 0.10.0 crash data exists at the time of writing.

## Deliberately not done

- **The Experimental playback engine does nothing yet on webOS 5 and newer.** [Pull request #1307](https://github.com/GLinnik21/plx-native/pull/1307) makes the choice of exported window per firmware major, from an evidence table that ships empty, and its own text says "no runtime change today"; [issue #1064](https://github.com/GLinnik21/plx-native/issues/1064) is still asking for testers on a newer television. The note says this and does not present the setting as a feature that changes playback there. No `Closes #1064` is made.
- **The Open Watch Party transport is not a feature.** [#1273](https://github.com/GLinnik21/plx-native/pull/1273) and [#1283](https://github.com/GLinnik21/plx-native/pull/1283) add a WebSocket codec and a libcurl transport with no user-facing surface, and the note does not mention them.
- **Surround audio is not mixed down by default** (owner decision recorded in [#1082](https://github.com/GLinnik21/plx-native/pull/1082)), so a file whose surround track the set cannot decode may still be converted by the server or refused under Force Direct Play.
- **MP3, Vorbis and TrueHD decoding in the app stays behind a debug gate.** Only the codecs whose row carries television evidence (DTS today) are enabled in production.
- **The new Russian, Polish, Dutch and Catalan wording was written by contributors and has not been reviewed by us.** The Dolby Vision setting's strings were machine-drafted in every language, with English and Russian read by the contributor ([#1156](https://github.com/GLinnik21/plx-native/pull/1156)).
- **The Sans-IO refactors** (store jobs, the player lifecycle machine, the route planner, the replay codec negotiation) change no behaviour a television owner would see and have no entry in the note.
- **Dependency bumps** to harfbuzz (15.0.0, then 15.1.0), fribidi 1.0.18 and sentry-native (0.17.5, then 0.17.6) change bundled library versions and are not in the note.

There is no new file the app writes, permission, listener, FIFO or path outside its own directories, and no new host (plex.tv is already contacted for the account). The one change is that the account token is now sent on a managed profile's seat, to the same host, for a read. The judgement recorded in the commit is that no action-required section is owed and that the read is disclosed in the note's Changed section; it is a judgement, and the owner should confirm it. `PRIVACY.md` was not changed; its general statement that the app talks to Plex services for account features is what covers it. Since the second candidate, [#1347](https://github.com/GLinnik21/plx-native/pull/1347) moves the bundled libass facade to ABI 5 (fonts borrowed from the app instead of copied), links `-lrt` for `clock_gettime` on firmware 6.4 and older, lowers its helper renderers' priority with `setpriority`, and adds a framebuffer-fetch pass when the extension is present; its body records three passes of the firmware-compatibility review and a load check on 4.4.2 through 11.2.0. The action-required check was re-run over `rc/v0.10.0-rc.2..HEAD` plus [#1349](https://github.com/GLinnik21/plx-native/pull/1349): its hits are the word token in a GL-extension parser, file headers whose path contains `/media/` and test fixture hashes. There is no new file the app writes, permission, listener, FIFO, path or host, so no action-required section is owed. Whether any of these changed the payload's `DT_NEEDED` set or file list is what the generated half records; this paragraph does not claim it.
