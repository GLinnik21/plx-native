## External compatibility reports known at release time

- 2026-10-30, [discussion 1167](https://github.com/GLinnik21/plx-native/discussions/1167): an LG OLED55C24LA (2022; the reporter wrote the version as the 2024 line, release 9), 0.9.0, Developer Mode. ## Known issues at release, with provenance

- **Direct play hangs on some webOS 5 and newer sets.** Tracked in [issue #1259](https://github.com/GLinnik21/plx-native/issues/1259), which groups #1096, #954 and #1166 and says the causes are not confirmed to be the same. [Pull request #1133](https://github.com/GLinnik21/plx-native/pull/1133), which preserves baseline audio codecs and sizes converted Opus, is named there as the candidate fix for #1096 and is in this release; no confirmation from that set is recorded. [Issue #1166](https://github.com/GLinnik21/plx-native/issues/1166) is closed after [#1263](https://github.com/GLinnik21/plx-native/pull/1263) (the Dolby Vision CRA case) and was reopened once in between; the note lists only the open ones.
- **The subtitle timing offset has no minus direction** ([issue #1284](https://github.com/GLinnik21/plx-native/issues/1284), open).
- **webOS 3.x** is outside the supported range; [issue #862](https://github.com/GLinnik21/plx-native/issues/862) is open and the note does not claim 3.x starts on this package.
- **The k5lp, k3lp and k6hp chip issues** ([#74](https://github.com/GLinnik21/plx-native/issues/74) and [#174](https://github.com/GLinnik21/plx-native/issues/174)) are closed (#174 as not planned, since every event came from 0.6.6 and none from 0.7.0 or later); the note keeps them as known issues because nothing proves them gone.
- **Crash reports.** [Issue #289](https://github.com/GLinnik21/plx-native/issues/289) (native crash reports with no frames on the crashed thread) is open. [Commit `959440fae`](https://github.com/GLinnik21/plx-native/commit/959440fae) ends the process without returning into libc `exit()` to stop the libcrypto lock crash behind Sentry PLX-NATIVE-P cluster A (28 of 43 events, 19 on 0.9.0, per the commit); the remaining events of that issue ([#1115](https://github.com/GLinnik21/plx-native/issues/1115)) are cause-undetermined, and no 0.10.0 crash data exists at the time of writing.

## Deliberately not done

- **The Experimental playback engine does nothing yet on webOS 5 and newer.** [Pull request #1307](https://github.com/GLinnik21/plx-native/pull/1307) makes the choice of exported window per firmware major, from an evidence table that ships empty, and its own text says "no runtime change today"; [issue #1064](https://github.com/GLinnik21/plx-native/issues/1064) is still asking for testers on a newer television. The note says this and does not present the setting as a feature that changes playback there. No `Closes #1064` is made.
- **The Open Watch Party transport is not a feature.** [#1273](https://github.com/GLinnik21/plx-native/pull/1273) and [#1283](https://github.com/GLinnik21/plx-native/pull/1283) add a WebSocket codec and a libcurl transport with no user-facing surface, and the note does not mention them.
- **Surround audio is not mixed down by default** (owner decision recorded in [#1082](https://github.com/GLinnik21/plx-native/pull/1082)), so a file whose surround track the set cannot decode may still be converted by the server or refused under Force Direct Play.
- **MP3, Vorbis and TrueHD decoding in the app stays behind a debug gate.** Only the codecs whose row carries television evidence (DTS today) are enabled in production.
- **The new Russian, Polish, Dutch and Catalan wording was written by contributors and has not been reviewed by us.** The Dolby Vision setting's strings were machine-drafted in every language, with English and Russian read by the contributor ([#1156](https://github.com/GLinnik21/plx-native/pull/1156)).
- **The Sans-IO refactors** (store jobs, the player lifecycle machine, the route planner, the replay codec negotiation) change no behaviour a television owner would see and have no entry in the note.
- **Dependency bumps** to harfbuzz (15.0.0, then 15.1.0), fribidi 1.0.18 and sentry-native (0.17.5, then 0.17.6) change bundled library versions and are not in the note.

## Release configuration

| | |
|---|---|
| flavour | `com.beb.plxnative` (stable) — the id users install; `FLAVOR: stable` is pinned in the release workflow's build job |
| cargo features | `RELEASE=1`, which drops `devtools` and `devtriggers` |
| built by | GitHub Actions, from the tag, at a path identical on every runner |
| toolchain | webOS NDK unchanged as far as this range records; Rust is the stable release `rust-modules/rust-toolchain.toml` pins (as v0.9.0's audit records after #816), unchanged in this range |

Changes to the build that a reviewer might look for: new bundled FFmpeg audio decoders and a resampler for the app's PCM paths ([#950](https://github.com/GLinnik21/plx-native/pull/950), [#1095](https://github.com/GLinnik21/plx-native/pull/1095)), the HarfBuzz, FriBidi and FreeType shaping calls and two bundled Noto faces for Arabic and Hebrew ([#1007](https://github.com/GLinnik21/plx-native/pull/1007)), the playback build matrix and the URI backend returning to the shipping binary but never selected by default ([#1276](https://github.com/GLinnik21/plx-native/pull/1276), [#1275](https://github.com/GLinnik21/plx-native/pull/1275)), an `exit()` interposer ([#1242](https://github.com/GLinnik21/plx-native/pull/1242)) and a WebSocket transport over libcurl. A new outbound host: the Player HUD gallery reads a registry at `huds.plxnative.com` ([#1243](https://github.com/GLinnik21/plx-native/pull/1243), [#1239](https://github.com/GLinnik21/plx-native/pull/1239)), accepting only a signed index, and fetches previews without credentials.
