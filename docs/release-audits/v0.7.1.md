# Release audit — v0.7.1

The evidence behind [the v0.7.1 release note](https://github.com/GLinnik21/plx-native/blob/v0.7.1/docs/release-notes/v0.7.1.md). Written for a webosbrew reviewer, a contributor auditing an old release, and us in a year. The section at the bottom is generated from the artifact that was published; everything above it was written before the release ran. This patch release is cut from `release/v0.7`, and CI will complete the generated section on that branch.

## What this release contains

- **Bundled Let's Encrypt roots for `*.plex.direct`.** Four roots (ISRG Root X1, X2, YR and YE) ship in the app. They are consulted only for a `*.plex.direct` address and only after the television's own trust store has reported an unknown issuer; the check is then repeated against them. Name, validity dates and the chain are still verified, verification is never switched off, and no other host uses the bundled roots.
- **Redirects followed one hop at a time.** Trailers and other media that the server redirects elsewhere are followed hop by hop with each host checked on its own, and the token is not sent to the redirect target.
- **Wrong-clock key path.** When the clock is wrong enough to fail a certificate's date check, a server that was previously verified is reachable by its remembered public key. A system toast is intended to say so. This came with the patch because the certificate fix builds on it. The reason line and clock glyph on a failed Home or Library screen are on trunk only and are not part of this line.
- **Failure messages.** Sign-in and the profile picker distinguish "this TV doesn't trust the certificate", "servers listed but none answered" and a real no-access (HTTP 401). The new strings are English only on this line, and the picker draws them as one line at body size (a host test measures them against the safe width).
- **Logs.** The event, crash and stderr logs are group-readable (0640) for Developer Mode collection and scrubbed of local addresses by the Rust side. [SECURITY.md](https://github.com/GLinnik21/plx-native/blob/v0.7.1/SECURITY.md) states the residual: lines written by the C side bypass the scrubber.

## External compatibility reports known at release time

One report, which concerns the same fix on trunk and not this release: an owner of an LG NANO81-series set on webOS 5, installed through Developer Mode, reported that 0.7.0 could not connect to a server whose certificate chains to ISRG Root YR, and confirmed the fix with a nightly build of trunk. The report is not repeated on v0.7.1. The earlier reports in [v0.7.0's audit](https://github.com/GLinnik21/plx-native/blob/release/v0.7/docs/release-audits/v0.7.0.md) stand as they were.

## Compatibility tiers, and what moved

Nothing moved. The tiers are v0.7.0's. The dev set's run covers the certificate path, a trailer preview and the redirects, and a debug build is not the release artifact; the webOS 5 report is a connection report on a trunk build and is not a playback claim for this version. The static loader check grades startup only.

## Known issues at release, with provenance

- **A server presenting a self-signed or private root is still not trusted.** The message tells the owner to update PlxNative, which does not help in that case. Known from the design of the fix: only the four bundled public roots are consulted.
- **The wrong-clock toast has not been seen on a device**, and neither has the picker's new wording on a real panel.
- Every other known issue in [v0.7.0's audit](https://github.com/GLinnik21/plx-native/blob/release/v0.7/docs/release-audits/v0.7.0.md) remains unless superseded above.

## Deliberately not done

- No automatic issuer download.
- No general CA bundle: only four Let's Encrypt roots, only for `*.plex.direct`.
- No "trust anyway" prompt.
- The reason line and clock glyph on a failed Home or Library screen stay on trunk.
- No translations of the new strings.
