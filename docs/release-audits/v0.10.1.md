**Written ahead of the release, from the repository alone.** This authored half was drafted against `origin/release/v0.10` at `f93e034dd`, which is five commits after the `v0.10.0` tag (the release was cut 2026-11-12), by a drafting agent that did not touch a television, build a package or run a suite. ## Deliberately not done

- **Nothing else from `main` is in this release.** The line takes labelled backports only; `main` has moved on and its other changes ship in the next minor. [#1382](https://github.com/GLinnik21/plx-native/pull/1382), a test-only change to a flaky timing test merged on `main` on 2026-11-14, is not on the line (`git log v0.10.0..f93e034dd` does not list it) and is not in the note.
- **No action-required section, and the decision was evaluated.** The trigger scan the release-notes standard asks for, run over every crate and `src` and `ci` in `git diff v0.10.0 f93e034dd` (the standard's own pathspec, `rust-modules/src src ci`, no longer covers the layer crates, so the scan was widened to `rust-modules`), found only: the interposer's four `/tmp/*_PRINT` literals, which `src/access.c` compares against and never opens or creates; `O_CREAT` and `0600` in the Linux-only C test fixtures under `ci/`, which create probe files for the test's own run; and internal seek-pause tokens in test code. None of the five changes adds a credential path, changes who can read a file the app writes, writes outside the app's own directories, adds a network destination or opens a listener. [#1370](https://github.com/GLinnik21/plx-native/pull/1370) changes which tags a stored crash report carries, and `PRIVACY.md` says so: the report's `release` is left out when the record names a different build than the one sending it, and it carries `crash.uploaded_by` (the app version that sent it) and `crash.build_id` (the build identifier of the build that crashed), which the same reports already carried. Nothing new is collected and crash reporting stays opt-in, so the note carries it under Fixed.
- **No chip gate on the `access()` interposer.** [#1438](https://github.com/GLinnik21/plx-native/pull/1438) answers the four probe paths on every set, not only the k6lp and k6hp ones: its body records that an independent review agreed with shipping it ungated, and that sets on other chips either do not make these calls or make them about once a frame. The note says the change was measured on one k6lp set and nowhere else.
- **The `/proc/self/cmdline` read per swap and per `glUseProgram` is not interposed.** The body says it deliberately does not interpose `fopen`, and that the remaining cost, the number of GL calls per frame, belongs to a separate follow-up.
- **No new feature, no setting, no string.** The note has no "What's new" section because none of the five adds one.
- **Wording not claimed:** that the C8's seeks are fixed by the merged code (its reporter ran an equivalent patch), that Continue Watching is fixed on a television, that Home is smoother on a k6hp set, or that Home changes on a 2019 set.

Changes to the build that a reviewer might look for. A new C source, `src/access.c`, is linked into the executable on Linux targets and exported with `-Wl,--export-dynamic-symbol=access` (`ACCESS_INTERPOSER_LDFLAG`), the route `src/exit.c` takes for `exit`, so the executable's dynamic symbols now include `access` beside `exit` and the Starfish interposer. `ci/check-elf.sh` asserts that export on the shipped binary, and `check-c-unit` gains two Linux-only legs (one with the interposer, one control without it) built from `ci/access-interpose-lib.c` and `ci/access-interpose-test.c`. `src/crashtrace.c` sets `errno = 0` once when the crash handler is installed, so the `__errno_location` PLT slot is bound before a signal can reach the interposer. A reviewer running `strings` will find `/tmp/API_PRINT`, `/tmp/SKIP_PRINT`, `/tmp/SHADER_PRINT` and `/tmp/GM_FPS_PRINT` in the binary: they are compared against and never opened. Behaviour changes the body states: LG's four debug switches (creating any of those files under `/tmp`) no longer take effect inside the app's process, and a non-NULL invalid path pointer passed to `access()` now faults in user space instead of returning `EFAULT` (a NULL pointer still reaches the kernel, and the app passes neither). No bundled library, outbound host or file written outside the app's own directories is added by any of the five; the package's actual payload, libraries and `DT_NEEDED` set are in the generated block, which this half does not type.
