# Release audit — v0.8.0

The evidence behind [the v0.8.0 release note](https://github.com/GLinnik21/plx-native/blob/main/docs/release-notes/v0.8.0.md). Written for a webosbrew reviewer, a contributor auditing an old release, and us in a year. The section at the bottom is generated from the artifact that was published; everything above it was written by a person before the release ran.

**Written ahead of the release candidate.** This authored half was drafted against `main` at `4a0dab4f`, before any 0.8.0 package, candidate or device suite existed, and it is to be completed by the maintainer before the release. Every place that is incomplete says "not run when this was written" or "not recorded when this was written", so the places to finish can be found by searching for those phrases. Nothing below was measured for this release; it records what the repository's own pull requests, issues and documents say, with their dates, and it says where they say nothing.

**Updated 2026-10-07 for the final release, against `main` at `00b7c742`.** Three release candidates were cut from this line: rc.1 (tag `rc/v0.8.0-rc.1`, 2026-10-06, from `a74f928f`), rc.2 (`rc/v0.8.0-rc.2`, 2026-10-07, from `89cd87e7`) and rc.3 (`rc/v0.8.0-rc.3`, 2026-10-07, from `d07086c5`), and the maintainer installed and tried them on the development set; no suite output or measurement from those trials is recorded in this repository, so the rows below still say what they said before. rc.3 was tried on the maintainer's set. The changes since it are host- and simulator-verified only: [#484](https://github.com/GLinnik21/plx-native/pull/484) (a held card springs back while the item menu opens; it repairs a motion regression that existed only between 2026-10-07 and rc.3, so it is not in the note) and the caption change that ends a focused caption at the end of a row on the card's right edge. Everything else this update adds to the note came in with [#480](https://github.com/GLinnik21/plx-native/pull/480), [#481](https://github.com/GLinnik21/plx-native/pull/481) and [#482](https://github.com/GLinnik21/plx-native/pull/482), whose pull requests each say they were not verified on a television.

v0.8.0 is the first trunk release since v0.7.0 (213 commits as of `00b7c742`, counted from the `v0.7.0` tag; 207 when this was first written). v0.7.1 was cut from the `release/v0.7` maintenance line and is not an ancestor of `main`; its fixes ([#381](https://github.com/GLinnik21/plx-native/pull/381), [#384](https://github.com/GLinnik21/plx-native/pull/384), [#390](https://github.com/GLinnik21/plx-native/pull/390), [#391](https://github.com/GLinnik21/plx-native/pull/391), [#392](https://github.com/GLinnik21/plx-native/pull/392) and [#443](https://github.com/GLinnik21/plx-native/pull/443)) reached `main` through their own commits, so v0.8.0 carries them. What trunk has beyond the v0.7.1 line for that work is the reason line and clock glyph that [#392](https://github.com/GLinnik21/plx-native/pull/392) puts on a failed Home or Library read-out, which v0.7.1's audit lists as "on trunk only". Most of the range is not user-visible: the split of the application into layer crates (`plx_base` through `plx_screens`), CI and build tooling, the site, tests and the repository's own tools. None of that is claimed in the note.

**Nothing moved on new evidence.** No television was added to the verified tier and no named third-party playback report arrived. The opt-in usage counts above are the nearest thing to new evidence and were deliberately not used to move a tier: they are counts from v0.6.6, not a named person on a named set watching this version. The static line carries v0.7.0's wording and must be checked against the generated matrix: this build adds a privately bundled library, `libass-plx.so.0`, whose own dependencies the generated half grades, so the loader result is this build's to state and not the previous one's. Platform release 3.9.3, which [issue #249](https://github.com/GLinnik21/plx-native/issues/249) concerns, is a firmware the static matrix holds no image for, so it is ungraded rather than "does not start".

**A second artifact is out of step and is the maintainer's to settle.** The compatibility rule is that a change to the claim is a change to this repository's note and to the package description in `webosbrew/apps-repo`. `docs/webosbrew-package.yml` was changed on 2026-09-26 to read "Video plays on sets from 2018 through webOS 11", resting on the opt-in usage counts above, while the release notes for v0.7.0 and this release keep the four-tier wording. Whether a pull request for that description exists is not recorded in this repository.

## Known issues at release, with provenance

- **Preferences that signing out does not clear.** `Mutation::ClearTenure` keeps the stored public preferences whole except the keys listed in `ACCOUNT_BOUND_PREFERENCES`, which is `server_key_pins` alone (`rust-modules/platform/src/storage/state.rs`). The plaintext-consent answers ([issue #385](https://github.com/GLinnik21/plx-native/issues/385), open since 2026-10-02), the per-library views ([#441](https://github.com/GLinnik21/plx-native/pull/441)) and the per-item subtitle timings ([#324](https://github.com/GLinnik21/plx-native/pull/324)) are in them, and the issue records that Delete all local data removes only `language` from that object. `PRIVACY.md` says signing out removes the unencrypted-connection answers, which the issue shows is not so. What remains holds a server's `machineIdentifier`, library and item identifiers and an account fingerprint, not a token. Not fixed in this release.
- **Some 2019 sets on LG's k5lp or k3lp chip, installed through Developer Mode, cannot play video.** The v0.6.x finding behind [issue #74](https://github.com/GLinnik21/plx-native/issues/74), listed in the README. The in-app Repair button has still not been run on an affected set; the one reporter repaired from a root shell.
- **2018 sets on platform release 3.9.3.** [Issue #249](https://github.com/GLinnik21/plx-native/issues/249), from opt-in reports over 90 days: nine such sets launched the app (v0.6.0 to 0.6.6), seven completed sign-in, and three sets on v0.6.5 asked to play eight times, each entering the player and logging a request and nothing after. Closed as not planned on 2026-10-01 because the firmware is ungraded and nobody with such a set has reported back. Whether 0.6.6, 0.7.0 or later behave differently is unknown.
- **k6hp crash** ([issue #174](https://github.com/GLinnik21/plx-native/issues/174), Sentry PLX-NATIVE-W). All four events came from one k6hp set running 0.6.6, which predates [#155](https://github.com/GLinnik21/plx-native/pull/155), [#168](https://github.com/GLinnik21/plx-native/pull/168) and [#171](https://github.com/GLinnik21/plx-native/pull/171); the issue was closed as not reproducible on 2026-09-28 with no event from 0.7.0 or a nightly in the 14 days before. Native crash reports still arrive without frames on the crashed thread ([issue #289](https://github.com/GLinnik21/plx-native/issues/289), open, "0.7.0 still affected"), so a recurrence may carry no stack.
- **Boost dialog released mid-film.** [#302](https://github.com/GLinnik21/plx-native/pull/302) measured the server answering 503 to a file read that carries an enhanced stream's session after its timelines have posted, so releasing the option falls back to a plain remux. [#474](https://github.com/GLinnik21/plx-native/pull/474) opens the file on a fresh session instead; its own body says the device has not been asked. Carried as a Help-test item, not a defect.
- **DTS is sent to the television only where its codec table lists it and the pipeline accepts it, and nobody has confirmed sound or sync** ([#264](https://github.com/GLinnik21/plx-native/pull/264); the issue it closed, [#221](https://github.com/GLinnik21/plx-native/issues/221), carries no recorded verification).
- **A library with many recommended shelves has no shortcut to its grid** ([issue #425](https://github.com/GLinnik21/plx-native/issues/425), open), a consequence of removing the shelf cap in [#428](https://github.com/GLinnik21/plx-native/pull/428) and [#429](https://github.com/GLinnik21/plx-native/pull/429).

What is unusual about this build, relative to v0.7.0:

- **A new bundled native library, `libass-plx.so.0`.** Built by `ci/build-libass.sh` from the pins in `ci/libass-dependencies.json`, with FreeType, FriBidi and HarfBuzz linked in statically, and loaded by the application by absolute path, so dependency symbols cannot collide with the firmware's font stack. Only the versioned `plx_ass_*` facade is exported. It is a new payload file; the generated half's payload inventory and bundled-library `DT_NEEDED` column are the evidence for what it needs, and its firmware verdict is the generated matrix's, not this paragraph's. The main binary's own `DT_NEEDED` list, `ci/expected-dt-needed.txt`, is unchanged since v0.7.0. [#255](https://github.com/GLinnik21/plx-native/pull/255) reports a firmware-linkage pass for the supported range and a source and artifact compatibility review; the release run repeats the grading.
- **Licences and corresponding source.** FriBidi is LGPL-2.1-or-later and is statically linked into `libass-plx.so.0`; FreeType, HarfBuzz and libass carry their own notices (`licenses/FreeType.txt`, `licenses/HarfBuzz-Old-MIT.txt`, `licenses/libass-ISC.txt`), as do ICU4X, `libm` and `qrcodegen` (`licenses/ICU4X.txt`, `licenses/libm.txt`, `licenses/qrcodegen.txt`). `ci/source_bundle.py` requires the libass pins and recipe files in the source bundle. That the attached source actually contains the FriBidi and FreeType archives is read from the generated half's licence and source sections, and the maintainer should confirm it there; this paragraph does not assert it.
- **New Rust dependencies.** The ICU4X crates (calendar, datetime, decimal, plurals and locale, with their data crates) and `qrcodegen`, linked statically for locale-aware formatting and the Settings → Language QR code ([#265](https://github.com/GLinnik21/plx-native/pull/265)); `rust-modules/Cargo.lock` is the list.
- **New payload files.** `pkg/le-roots.pem`, four public Let's Encrypt roots consulted only for a `*.plex.direct` address after the television's own store reports an unknown issuer (shared with v0.7.1; pinned by SHA-256 in `ci/check-package.py`); a Belarusian localized `appinfo.json` (`pkg/resources/be/appinfo.json`); and `libass-plx.so.0` above.
- **One new outbound host in source.** `clients.plex.tv`, for reading and changing the active profile's audio and subtitle language preferences, with that profile's own plex.tv token ([#264](https://github.com/GLinnik21/plx-native/pull/264)). A source grep against v0.7.0 found no other non-test host. The generated host-string table is the measurement.
- **One new request to an existing host.** `GET /api/v2/user` on plex.tv, made only when discovery returns no servers, with a 5 second deadline, to name the signed-in account on screen ([#383](https://github.com/GLinnik21/plx-native/pull/383)). The name is not logged, written or sent.
- **Log files are group-readable.** The event, crash and stderr logs under `/tmp` are opened by `src/main.c` with mode 0640 where v0.7.0 created them 0600, so a Developer Mode shell in the app's group can fetch them; the Rust side scrubs local addresses and the C-side lines skip that scrubber. First shipped in v0.7.1, whose audit records it; `docs/install-and-verify.md` and `SECURITY.md` carry the account, and the generated half measures the mode only indirectly, so the maintainer should confirm it on the installed files.
- **New files written.** An artwork cache, bounded by the pull request to a fixed byte and file count (`docs/image-cache.md` records both), in `/media/developer/<id>-imgcache`, falling back to `/media/internal/.<id>-imgcache` and then to the app directory (`rust-modules/base/src/paths.rs`). It holds compressed image bytes under SHA-256 file names and no token or URL, and signing out sweeps it. The new preferences above are written into the existing session record.
- **Plaintext HTTP, consent-gated.** A credential may now travel over plaintext HTTP to a private numeric address only with a live grant bound to the identity generation, the network generation, the machine identifier and the exact origin ([#251](https://github.com/GLinnik21/plx-native/pull/251)); `docs/install-and-verify.md` and `SECURITY.md` carry the account of it.
- **This release does not promote a candidate.** The last one, rc.3 (`rc/v0.8.0-rc.3`), was cut from `d07086c5`; `main` has taken [#484](https://github.com/GLinnik21/plx-native/pull/484) and the caption change since, and `release.yml` refuses a promotion whose tree differs from the candidate's. The tree published here has not itself been installed as a candidate.
