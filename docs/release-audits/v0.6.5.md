The evidence behind [the v0.6.5 release note](https://github.com/GLinnik21/plx-native/blob/v0.6.5/docs/release-notes/v0.6.5.md). Written for a webosbrew reviewer, a contributor auditing an old release, and us in a year. The section at the bottom is generated from the artifact that was published; everything above it was written before the release ran. This patch release is cut from `release/v0.6`, and CI will complete the generated section on that branch.

## What this release contains

- **Issue #81 IPv6 log redaction.** The existing local and outbound scrub sequence now recognizes compressed and expanded IPv6, bracketed literals with ports, IPv4-mapped tails, and the bare address-plus-port spelling emitted by probe diagnostics. Unambiguous loopback and unspecified addresses retain the existing exception; a complete IPv6 literal takes precedence over a possible trailing decimal port, so forms such as `::1:80` cannot inherit the loopback exemption. Regression cases cover positive forms and false positives such as timestamps, MAC addresses, Rust paths, ordinary key/value text, malformed brackets, and out-of-range ports. This changes logging only; it does not add IPv6 connection selection or transport support.
- **Issue #74 confirmed sandbox-repair backend and UI.** The existing affected-SoC/missing-device gate exposes a neutral, Cancel-default confirmation. Only confirmation sends one fixed command to Homebrew Channel's existing root execution service. The backend validates the current app id and exact install path, checks the service uid and source device, checks the remote target node and fresh app-side readability, and accepts only an exact success marker. One accepted attempt is terminal for the process, including timeout, because cancellation does not prove the remote child stopped. No repair is attempted at startup or on an ordinary playback request.
- **A separate experimental non-root procedure.** Offline firmware analysis found that the inspected webOS 4.10.2 launcher reads a valid signed `jail_app.conf` pair from the selected application directory. LG's currently downloaded 4.10.0 pair contains the relevant `rtkmem` rule and passed detached pair-integrity verification. The guide uses direct LG downloads, Dev Manager backup and rollback, and does not redistribute the files or firmware code. Trust-chain acceptance, application-directory writability, and end-to-end playback remain untested on an affected non-rooted set.

## External compatibility reports known at release time

[Robert](https://github.com/RobertSmits) reported the v0.6.3 failure on a k5lp set and later confirmed in [issue #74](https://github.com/GLinnik21/plx-native/issues/74) that playback worked after the equivalent `native` jail setup command was run from a root shell. The attached transcript records creation of the missing jail character-device entry. This is evidence for the operation and affected condition, not evidence that the new UI path has run.

The prior playback report remains [mariotaku](https://github.com/mariotaku)'s v0.2.1 run on an LG 65UP7560AUD at platform release 6.5.2 in [issue #22](https://github.com/GLinnik21/plx-native/issues/22). No third party has reported playback with v0.6.5.

## Compatibility tiers, and what moved

No firmware moves to a broader playback tier. The established loader boundary remains webOS 4.0 and newer. The dev set adds UI and root-service reachability evidence only; the affected report predates this release and confirms the underlying operation rather than the button. The exact k5lp/k3lp scope remains community-tier evidence and is deliberately not generalized to other sandbox failures.

## Known issues at release, with provenance

- **The affected-device button run is outstanding.** The failure and successful root-shell operation are recorded in [the issue #74 repair ledger](../measurements/issue74-sandbox-repair.md). The new command has not been submitted through the app on that hardware, so success, timeout behavior, relaunch, and persistence are not claimed.
- **The non-root procedure is experimental.** [Its evidence ledger](../measurements/issue74-non-root-sandbox.md) records firmware analysis and LG-file inspection, but no file was changed on a TV. Write permission, TV trust-chain acceptance, playback, and update/reboot persistence remain open.
- **IPv6 addresses in existing logs remain.** Issue #81 demonstrated plain IPv6 literals in event logs. v0.6.5 scrubs newly written lines only; it does not rewrite old files or copies already shared. v0.6.4 is confirmed affected, while the exact scope of earlier releases remains uncertain.
- Every known issue in [v0.6.4's audit](https://github.com/GLinnik21/plx-native/blob/release/v0.6/docs/release-audits/v0.6.4.md#known-issues-at-release-with-provenance) not superseded here remains, including the unconfirmed real-`keymanager3` recovery path and the one-off libmali SIGSEGV.

## Deliberately not done

- No automatic root action was added. The app reaches Homebrew Channel only after the user selects Repair and confirms the neutral dialog.
- No general jail configuration replacement is attempted by the rooted path. The upstream installer-wide workaround was reverted because it did not solve different sandbox failures on some newer models; this release confines the action to the detected k5lp/k3lp missing-device case.
- No affected owner was held as a release blocker. The normal v0.6.5 release includes the guarded repair with its uncertainty stated, while the issue remains the collection point for post-release evidence.
- No token-rotation claim accompanies issue #81. The demonstrated disclosure is an IPv6 address in an event log, with no evidence in that report of a credential leak.

## Release configuration

| | |
|---|---|
| flavour | `com.beb.plxnative` (stable) — the id users install; `FLAVOR: stable` is pinned in the release workflow's build job |
| cargo features | `RELEASE=1`, which drops `devtools` and `devtriggers`; the repair UI and user-confirmed backend remain present |
| built by | GitHub Actions, from the tag, at a path identical on every runner |
| toolchain | webOS NDK and Rust nightly pinned by the release workflow; final values are generated from the release run |

The rooted repair reuses the existing Homebrew Channel LS2 endpoint and introduces no native-library binding, new bundled dependency, new outbound host, startup root call, or automatic write outside the app's existing runtime behavior. The experimental guide directs users to LG's download endpoint; the release package does not contain LG's configuration files.
