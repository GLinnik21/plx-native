# Release audit — v0.6.6

The evidence behind [the v0.6.6 release note](https://github.com/GLinnik21/plx-native/blob/release/v0.6/docs/release-notes/v0.6.6.md). Written for a webosbrew reviewer, a contributor auditing an old release, and us in a year. The section at the bottom will be generated from the published artifact; everything above it was written before the release ran. This patch release is being prepared from the 0.6 maintenance line.

## What this release contains

- **Private DB8 session and consent state.** A packaged `<appid>.storage` native service owns one
  fixed-ID private DB8 object. The object contains DB8 metadata plus an opaque typed JSON document;
  Session, reporting consent, operation receipts and a `ClearTenure` tombstone share its CAS. New
  firmware attempts Keymanager3 and may fall back to a diagnostic-bearing private-DB8 ACL-only
  envelope for fresh auth; ordinary mutations never downgrade healthy ciphertext. The policy for
  reported webOS majors 1–4 selects ACL-only directly; runtime evidence currently covers 4.10.2
  only. Published
  v0.6 files are migration sources, never a live fallback.
- **Bounded asynchronous persistence.** One shared FIFO worker performs session and reporting writes away from UI and authentication locks. Per-operation receipts distinguish pending, durable, uncertain and failed writes. The UI retains relevant failures, offers an identity-guarded retry of the current snapshot, and prevents an older completion from restoring signed-out state.
- **Asynchronous cold boot.** Session and reporting records load before the normal routes become available without performing storage I/O on the UI thread. The same ordering keeps reporting disabled until its stored decision is known.
- **Background presentation protection and lifecycle diagnostics.** Background lifecycle events close the frame-presentation gate during cold boot and normal routing, revoke borrowed Wayland handles, and require a fresh window query before the first foreground frame. Consent-gated crash reports retain a bounded lifecycle breadcrumb sequence; the original one-off libmali crash was not reproduced and is not labelled fixed.

The final DB8 debug package reproduced and then closed an old-firmware serialization defect. When
the canonical state was initially stored as a flattened DB8 object, webOS 4.10.2 inserted a
six-character `_id` into `operations[0]`; strict decoding correctly refused that modified schema.
The compatibility reader removed only that proven ledger field and rewrote the record as
`{_id,_kind,_rev,state}`, with `state` opaque to DB8. A fresh app process then reported a stored
account, PMS credential, dialable server and local eligibility, reached Home without QR, and
persisted later Home/settings edits. The observed inner record reached revision 15 with both
migration domains complete, auth present and no nested DB8 IDs. On this old firmware the logged
`persisted_plaintext` class means the explicit private-DB8 ACL-only tier; it is not a newer-firmware
plaintext fallback.

After the authenticated-receipt and Keymanager fallback work landed, the final release-built debug
package was installed over that same DB8 state without clearing it. A new app process loaded the
stored account, PMS credential, local server and profile roster, reached the profile route without
QR, and persisted a later roster refresh as ACL-only on webOS 4.10.2. The final debug IPK passed all
package assertions. This is an old-firmware update/restart proof, not newer-firmware Keymanager
runtime or power-cycle evidence.

The [exact 11.2 firmware and injected-trace ledger](../measurements/db8-keymanager-webos11-static-proof-2026-09-12.md)
records reachable DB8/Keymanager code paths, lost-reply simulations, and seven credential-free
events fetched back from development Sentry. The live ingest proof caught and fixed one field that
Sentry's own sensitive-data filter had hidden. Static inspection and injected replies still do not
claim a real newer television's Keymanager/OPTEE runtime.

The first update left the legacy Session byte-identical across installation, installed a stripped binary matching the IPK, and imported the account and profile identity; the profile avatar refreshed normally. Its pre-upgrade `home_pins` was already empty, so this is not evidence that an older nonempty Home answer migrated. After Home choices were recorded in v0.6.6, the corrected same-version package update again installed the matching packaged binary and left the canonical Session and Consent byte-identical across installation. The next boot retained the account token, Home pins, playback quality and recent searches, and the user confirmed Home opened without repeating the choice. No cleanup error appeared. This did not exercise sign-out, consent withdrawal, playback, a background/foreground cycle, a power cycle or a real-Key-Manager migration.

## Known issues at release, with provenance

- **Device migration coverage has one explicit gap.** The direct v0.6.0-to-v0.6.6 update preserved a plaintext account and profile, but its legacy source already had an empty Home answer. The corrected same-version update preserved a nonempty asked answer with three libraries on and two off, plus playback quality and recents. Together they do not prove a direct older-v0.6-to-v0.6.6 migration of nonempty Home pins.
- **Real-Key-Manager coverage remains incomplete.** Exact webOS 11.2 firmware decompilation proves
  the required DB8/installer/Keymanager3 call paths and worker tests exercise the secure contract,
  but no current candidate has sealed and reopened a real protected session on newer hardware.
- **DB8 capacity is not device-proven at the configured maximum.** Host tests cover the complete
  512 KiB canonical/string/frame boundary and the inspected newer firmware grants a 10 MiB owner
  quota, but neither proves every firmware's per-object or LS2 message limit at that boundary.
- **IPv6 addresses already present in older logs remain.** v0.6.5 redacts newly written lines but does not rewrite existing files or copies already shared; v0.6.4 is confirmed affected, while the exact scope of earlier releases remains uncertain.
- **The affected-device sandbox repair remains outstanding.** The rooted in-app Repair button has not been run on the affected k5lp/k3lp set, and the non-root procedure remains experimental; [the v0.6.5 audit](https://github.com/GLinnik21/plx-native/blob/release/v0.6/docs/release-audits/v0.6.5.md#known-issues-at-release-with-provenance) records their provenance and limits.
- **The original libmali SIGSEGV remains unresolved.** The lifecycle change closes independently demonstrated stale-handle and background-presentation defects and records more evidence, but the reported crash was not reproduced and its fault offset could not be symbolized against the development television's different driver build. The [measurement ledger](https://github.com/GLinnik21/plx-native/blob/release/v0.6/docs/measurements/pr84-wayland-lifecycle-2026-09-11.md) keeps that boundary explicit.

## Deliberately not done

- No 0.7 forward-port is included or implied. This release remains on the 0.6 maintenance line.
- No unverified save is presented as durable. Fresh auth may be durably kept in private DB8 through
  the explicit, diagnosed ACL fallback after verified Keymanager or ACL readback; failed or
  uncertain commits remain visible. Account reset blocks a new sign-in tenure until the shared
  `ClearTenure` tombstone is durable.
- No downgrade, uninstall/reinstall, filesystem rollback, physical-loss or lost-key guarantee is made. Legacy files are forward-migration inputs, not a second live store.
- No CI publication, published-asset verification, newer-reporter upgrade, power-cycle, real-Key-Manager migration, playback, background/foreground, sign-out-cleanup or consent-withdrawal result is claimed. The local artifact gates and development-television updates do not substitute for those separate results.

## Release configuration

| | |
|---|---|
| flavour | `com.beb.plxnative` (stable) — the id users install; `FLAVOR: stable` is pinned in the release workflow's build job |
| cargo features | `RELEASE=1`, which drops `devtools` and `devtriggers` |
| built by | GitHub Actions, from the tag, at a path identical on every runner |
| toolchain | webOS NDK and Rust nightly pinned by the release workflow; final values are generated from the release run |

The package now supplies a private native storage service rather than a writable state directory.
Its only listener is a mode-0600 Unix socket in the app's transient `/tmp` runtime; it adds no
outbound host or automatic root action. Final package contents and byte-derived properties remain
generated evidence.
