# Release audit — v0.9.0

The evidence behind [the v0.9.0 release note](https://github.com/GLinnik21/plx-native/blob/main/docs/release-notes/v0.9.0.md). Written for a webosbrew reviewer, a contributor auditing an old release, and us in a year. The section at the bottom is generated from the artifact that was published; everything above it was written by a person before the release ran.

**Written ahead of the release, from the repository alone.** This authored half was drafted against `origin/main` (337 commits after the `v0.8.0` tag, cut 2026-10-07) by a drafting agent that did not touch a television, build a package or run a suite. Nothing below was measured for this release: it records what the repository's own pull requests, issues, discussions and documents say, with their dates, and it says where they say nothing. No release candidate for 0.9.0 exists as a tag (`rc/v0.9.0-rc.*` is absent), no `release/v0.9` or `release/v0.8` maintenance line exists, and 0.8.0 is the only release tag after 0.7.1; so unlike 0.8.0 this note owes no "everything fixed in" line for a maintenance release. The release dispatcher is to add device results where the rows below say "not run when this was written".

**What moved, and why.** The two new reported-tier entries (2025 and 2018) are single reports on 0.8.0 and move only their own lines. Nothing was added to the verified tier. Three 3.x reports (platform releases 3.9.0, 3.9.4 and 3.4.3) are on nightly or branch builds and are described as such; none promotes a tier, because the project does not support webOS 3. The README's own known-issue row for platform release 3.9.3 and `docs/compatibility.md` already carry this evidence.

**A second artifact is out of step and is the maintainer's to settle.** A change to the claim is a change to this repository's note and to the package description in `webosbrew/apps-repo`. `docs/webosbrew-package.yml` was edited in this range (it now says a Profile 7 film is converted to Profile 8.1) but still reads "Seeking on webOS 5 and newer takes a slower route. ## Known issues at release, with provenance

- **Some 2019 sets on LG's k5lp or k3lp chip, installed through Developer Mode, cannot play video.** The v0.6.x finding behind [issue #74](https://github.com/GLinnik21/plx-native/issues/74), listed in the README; the issue is closed as completed but the README still lists the limitation, and the in-app Repair button has still not been run on an affected set.
- **webOS 3.x.** Seeking reloads the stream there by design ([#578](https://github.com/GLinnik21/plx-native/pull/578), [#581](https://github.com/GLinnik21/plx-native/pull/581)); [issue #862](https://github.com/GLinnik21/plx-native/issues/862) is open but describes the 0.8.0 failures #578 fixes (see above), so the note carries it as fixed; [issue #249](https://github.com/GLinnik21/plx-native/issues/249) was closed as not planned on 2026-10-01 and the prebuilt 0.8.0 is the build it describes. The fix for the missing Feed symbol is [#578](https://github.com/GLinnik21/plx-native/pull/578)'s run-time resolution, tested only by its author and by nightly users. Whether the release package behaves like the nightlies is unknown until it is run.
- **k6hp crash** ([issue #174](https://github.com/GLinnik21/plx-native/issues/174), Sentry PLX-NATIVE-W): closed as not planned; no reproduction. Native crash reports still arrive without frames on the crashed thread ([issue #289](https://github.com/GLinnik21/plx-native/issues/289), open), and [#632](https://github.com/GLinnik21/plx-native/pull/632) added symbols for the bundled libraries and more contexts to the fallback report, which has not been seen to help in the field.
- **Seek without reload on webOS 5 and newer** ([#713](https://github.com/GLinnik21/plx-native/pull/713)): forced on the development set only.
- **Dolby Vision Profile 7 conversion** ([#825](https://github.com/GLinnik21/plx-native/pull/825)): no device run recorded; the licence and notice entries for the added crates are in the repository.
- **DTS.** [#899](https://github.com/GLinnik21/plx-native/pull/899) makes the server's spelling `dca` direct-play on a set whose codec table lists DTS; nobody has confirmed sound or sync on a television ([#898](https://github.com/GLinnik21/plx-native/pull/898), [#899](https://github.com/GLinnik21/plx-native/pull/899) and the discussion that prompted them, [discussion 695](https://github.com/GLinnik21/plx-native/discussions/695)). DTS-HD MA 7.1 feeds the core only.
- **Rare empty pages and Home refresh misses.** Carried from v0.8.0's audit ([#480](https://github.com/GLinnik21/plx-native/pull/480)); [#858](https://github.com/GLinnik21/plx-native/pull/858), [#860](https://github.com/GLinnik21/plx-native/pull/860) and [#861](https://github.com/GLinnik21/plx-native/pull/861) reduce late frames on key presses and held paging, and no whole-release bench was recorded here.
- **Frame pacing.** [#843](https://github.com/GLinnik21/plx-native/pull/843) reports bursts of late frames about 11 s apart on the development set that it attributes to the compositor's chain and leaves undetermined; a long library name makes the live capsule glass cost more of the GPU budget (7.1 percent of scroll frames over budget against 1.9 percent with a short name, per the pull request), and the owner's decision on freezing it is open there.
- **Translations.** Italian, French, German, European Portuguese and Hungarian were contributed and, are contributions; [#652](https://github.com/GLinnik21/plx-native/pull/652) documents that translations are accepted after native-speaker review, and no review is recorded here. The Belarusian and Spanish strings added after v0.8.0 were checked against dictionaries only (Belarusian: skarnik.by and verbum.by).
- **Carried from v0.8.0's audit, unchanged and not re-examined:** Auto quality has only been exercised in a laboratory; relay-only and encryption-required servers are reached but not watched end to end; the in-app sandbox Repair button; the one-off libmali crash on the 0.6 line.
- **Issues deliberately dropped from the note's list.** [Issue #385](https://github.com/GLinnik21/plx-native/issues/385) (consent answers surviving sign-out) is closed, fixed by [#589](https://github.com/GLinnik21/plx-native/pull/589) and [#673](https://github.com/GLinnik21/plx-native/pull/673); `ACCOUNT_BOUND_PREFERENCES` now lists the plaintext answers, the track memory, per-profile settings, subtitle timings, Library views and the last Library (read from `rust-modules/platform/src/storage/state.rs` on `origin/main`).
