# Release audit — v0.7.0

The evidence behind [the v0.7.0 release note](https://github.com/GLinnik21/plx-native/blob/main/docs/release-notes/v0.7.0.md). Written for a webosbrew reviewer, a contributor auditing an old release, and us in a year. The section at the bottom is generated from the artifact that was published; everything above it was written by a person before the release ran.

v0.7.0 is the first trunk release since v0.6.0. The 0.6.1–0.6.6 patches were cut from the `release/v0.6` maintenance line; their storage, sign-in and consent work reached `main` in the forward-port [#105](https://github.com/GLinnik21/plx-native/pull/105) (`6f78842e`), and the individual fixes (the k5lp/k3lp Load race and sandbox repair, IPv6 redaction, background presentation) were re-applied to `main` separately. A 0.6.x user upgrading keeps every one of them.

**`pipe_replay_after_eos` was a reproducible regression, found and fixed this cycle.** Tracing it against `235e5199` (2026-09-12) found the DEV replay arm — not the production Up Next handoff, and not user-visible — deciding from the parked route instead of the Up Next handoff; the harness case had gone unexercised against the fixed behaviour (LG checklist item #46) since that commit without anyone noticing, because the regression was confined to the arm the harness itself drives. Fixed on this branch by "dev: the replay-after-EOS arm decides from the Up Next handoff, not the parked route (regression from 235e5199)"; re-run passes twice, all 10 assertions. The pipeline tier's other first-run failure, `pipe_abr_down_staircase`, did not reproduce on a solo re-run — a flake.

**Three of the 32 graded `--server` cases failed; one is a known-carried issue, one was a harness gap this release closed, one is a flake.**

- `seek_transcode` failed once and passed on a solo re-run — a flake.
- `audio_switch_native` failed on harness drift, not app behaviour: #210 made the file's own default track the start pick, so the case's row-0 pick had become a no-op. - `subtitle_image_pgs` fails exactly as it did in v0.6.0's audit: every playback assertion passes but no `image cue […]` line ever appears. Unchanged known issue, not investigated further this cycle. Fixed in `ci/build-ffmpeg.sh` with a host regression test (`make check-ffmpeg`); that the audited item's track is compressed is inferred, not read, so the case still needs a device re-run.

`offline_play`, `offline_play_v6` and `offline_pick_cached` **SKIPPED**: all three need a real stored sign-in on the debug install, which this pass did not create — this pass made no account writes.

## Landed after the first device pass, and the second pass over them

Seven changes reached `main` after the pass above ran (after `a788b27a`), and an eighth, #242, after the second pass. Each was host-tested and reviewed, then a second device pass ran a debug build of `3a30a017` on the same television under `--guest`, 2026-09-25. Four changes passed there as they were meant to be exercised: #234, #235, #237 and #239. #236 passed only for shelves that land before the grid; the grid-first ordering it changes was exercised on the host alone. **#238 is still pending the device pass**, and #237's one new finding is fixed by #242, which has not run on the television. The pass started no film from a page by hand, so no film's Play after a trailer was tried.

**Account writes this pass made, all to the Guest profile of the maintainer's own account.** The explicit PGS pick under #235 is `PUT /library/parts/{id}` (`route::decision::put_selection`, logged as `select streams: … -> HTTP 200`), which the server keeps as that profile's audio and subtitle selection for the item; it stays in force for later runs, which is why `subtitle_image_pgs` passing alone is not evidence of the pick. The `--server` harness clears each case item's resume point with `/:/unscrobble` before the case, seeds `/:/progress` where a case declares a `viewOffset`, and its cases play films, which report timelines to the same profile. No other profile's history or selection was touched. None of the eight changes a persisted format: no DB8 `plxstate` kind or record, session/identity store, consent record, setting, or on-disk cache is written differently, so the 0.6.x → 0.7.0 migration evidence above is not affected by them.

- **Art tiles cover-crop instead of stretching** ([#234](https://github.com/GLinnik21/plx-native/pull/234), `79c2d354`). Cast/person portraits, posters, the profile chip avatar and the player info panel's still are drawn through one aspect-preserving UV crop. **Passed on the TV, by eye:** a detail page's cast headshots render round and in proportion.
- **Bundled FFmpeg built with zlib** ([#235](https://github.com/GLinnik21/plx-native/pull/235), `20518dc6`), the root cause of `subtitle_image_pgs` above. Host regression test `make check-ffmpeg` over an mkvmerge fixture (compressed and uncompressed PGS, VobSub, SRT). **Passed on the TV:** a real mid-playback pick on an item whose six PGS tracks carry mkvmerge v33.1.0 content compression (`select streams: part=… audio=… sub=… -> HTTP 200`) was followed by new `image cue [603045ms] 371x61 …` lines. `subtitle_image_pgs` passed 8/8, but that case alone does not prove the pick decoded, because the server's per-user selection is sticky; the explicit pick is the evidence. See Release configuration for the new `libz.so.1` dependency.
- **Library DOWN lands on the first shelf when shelves arrive after the grid** ([#236](https://github.com/GLinnik21/plx-native/pull/236), `569855ca`). A seat the page chose itself follows the head when shelves land; any reader action or restored seat releases it. **Passed on the TV** on Movies and on Movies → Shows: the first DOWN reached a shelf. In that run the shelves landed before the grid, so the grid-first ordering this change is about was exercised on the host only.
- **Profiles read-out has a focused Back; the account menu hides a refused Change profile** ([#237](https://github.com/GLinnik21/plx-native/pull/237), `e66b644b`). The refusal verdict (`SessionInit::switch_refused_for`) is in memory only, keyed to the identity, and retired by sign-out or any committed roster; a relaunch asks plex.tv again. **Passed on the TV** under `--guest`: the read-out shows a focused Back, Back returns, and Change profile is hidden from the account menu. **New finding, fixed by [#242](https://github.com/GLinnik21/plx-native/pull/242), host-verified, device pending:** the account menu then opened with focus on Sign out.
- **BACK from the player returns to the detail page** ([#238](https://github.com/GLinnik21/plx-native/pull/238), `6d0b8e5b`). A regression from [#178](https://github.com/GLinnik21/plx-native/pull/178): a repeated push of the player during the page dip replaced the prepared player and lost its origin, so BACK, Stop and EOS fell back to Home. - **Test-only flake fix** ([#240](https://github.com/GLinnik21/plx-native/pull/240), `8fddd1d4`); the new lock assertions are `#[cfg(test)]`. No shipped behaviour.
- **Trailer previews stop at EOS and off their page, never report to the account, and follow redirects** ([#239](https://github.com/GLinnik21/plx-native/pull/239), `3a30a017`). A preview whose Original open failed could be rescued onto HLS and post `timeline playing` to the viewer's account every ten seconds while playing off-screen; a preview is now marked at landing and the timeline lease, the stop scrobble and the Original→HLS rescue all refuse it. This covers the background preview, including its full-screen mode, and nothing else: a trailer started from the item menu's Play Trailer goes through `route::decision::request_play` with `preview: false` (`app/input.rs`'s `Action::PlayTrailer`), so it takes a timeline lease and a stop scrobble like any playback. Trailers are new on this line, so only 0.7.0 nightlies could have sent such reports. Plaintext progressive, seek and HLS opens now follow up to five 3xx hops, forwarding the token only to the original origin; HLS refuses any hop off the PMS origin. **Passed on the TV:** a detail page autoplayed its trailer (`preview: Binding->Playing (picture) rk=51`); the Plex-hosted trailer's redirect went through a real CDN (`stream: redirect 302 -> https://<host>/video.mp4 hop=1 same_origin=false`, then `ff: open https status=200`); at its end `preview: EOS — stopping the preview engine` and `preview: Stopping->Idle (eos)` followed, the video plane unbound and nothing re-buffered; the next detail page autoplayed its own trailer; and BACK mid-trailer gave `preview: Playing->Stopping (halt)`. The logs carry no timeline or scrobble line for any preview. Not exercised: a suspend during a preview, and a film's Play after a trailer, which would write to the account. The failure that play used to hit, `live Engine belongs to another Load attempt`, never appeared.
- **Menus never open with focus on a destructive action** ([#242](https://github.com/GLinnik21/plx-native/pull/242), `7d739317`). A shared `Row::destructive` / `TableView::opening_row` / `open_sections` in `ui/table.rs` opens a menu on its first non-destructive row. The account menu no longer opens on Sign out once Change profile is hidden, including when the roster verdict arrives while the menu is open; the item menu opens a watched episode on Play from Start rather than Mark as Unwatched, and Remove from Deck is tagged the same way. Host-verified with tests watched red then green. **Pending the device pass.**

**Second-pass harness results.** `audio_switch_native` failed with `menupick: row 1 already active — no commit`: the server's sticky per-user stream selection had drifted, so the case's pick was a no-op. That is harness state, the same class as the first pass's drift on this case. Four `auto_*` cases skipped because they need a conditioned link. `offline_play`, `offline_play_v6` and `offline_pick_cached` skipped because their precondition checks the legacy `…debug-auth.json` file rather than the DB8 record the app now stores its sign-in in. ## Known issues at release, with provenance

- **k6hp crash** ([issue #174](https://github.com/GLinnik21/plx-native/issues/174), Sentry PLX-NATIVE-W). Seen only in opt-in crash reports from k6hp sets; the evidence points at an abort from C code. Not reproducible here — the dev set is an M19 board. This release does not fix it; #155, #168 and #171 make the next occurrence arrive with the panic and a native backtrace.
- **Unstyled ASS subtitles on direct play** ([issue #73](https://github.com/GLinnik21/plx-native/issues/73)). The client renders ASS as plain text. The reporter confirmed in the issue that forcing a transcode by picking a lower quality makes the server burn them in with styling. Unchanged in this release.
- **Auto is laboratory-exercised only** — one television, one server, `tools/netcond.py`. #209 and #213 bound every blocking leg of an active fetch; that was measured the same way and changes nothing about field coverage.
- **Playback on webOS 5, 7, 8, 9, 10 and 11 is unverified by anyone on this version.** The OLED65CX6LA report (platform release 5.6.2) is sign-in only.
- **Platform release 10.3.1 refusing every server transcode**: the generalized Load-envelope fix (`4e377aa8`, before v0.6.0) is still not re-run on that hardware; [docs/webos10-resource-allocation.md](https://github.com/GLinnik21/plx-native/blob/main/docs/webos10-resource-allocation.md) says so in its status line. Carried as a Help-test item, not as a present-tense failure.
- **Relay-only and encryption-required servers** are reached but not watched end to end. #104 and #183 changed which address is chosen and when a stored one is reused; neither was watched against those server shapes.
- **Real Key Manager sealing is still not device-proven** on a webOS 5+ set; carried from v0.6.6's audit unchanged.
- **The in-app sandbox Repair button has not been run on an affected set.** The affected reporter repaired from a root shell and the repair persists, so the issue closed; the button itself remains unexercised on k5lp/k3lp hardware.
- **The one-off libmali SIGSEGV** recorded on the 0.6 line remains unresolved; carried unchanged.
- **IPv6 addresses already written into older event logs** are not rewritten; new lines are redacted since v0.6.5 (`959ae21b` on this line). Residual only.
- **https HLS redirects are not origin-checked** (follow-up to [#239](https://github.com/GLinnik21/plx-native/pull/239)). On an https server connection, libcurl follows an HLS playlist redirect itself (`CURLOPT_FOLLOWLOCATION`, as before #239), does not check the target's origin, and the playlist is still parsed against the requested URL rather than where it landed. The plaintext path enforces both. A TLS→plaintext downgrade is refused, certificate verification stays on, and the token travels in the requested URL's query, which libcurl does not copy onto the redirected request. Closing it needs the effective URL from curl (a new `curl_easy_getinfo` binding with its firmware-compatibility review) or turning curl's own following off for HLS. Not fixed in this release.
- **A DOWN pressed before a library's shelves land** still leaves the reader in grid row 0 while the shelves commit above it; [#236](https://github.com/GLinnik21/plx-native/pull/236) fixes the seat the page chose itself, not one the reader chose. Pre-existing.
- **The PIN verifier cached for offline profile switching** (`Session::profiles`, `PinVerifier`, PBKDF2-HMAC-SHA-256) is disclosed in the note's action section with its residual: a four-digit keyspace is exhaustible by anyone who can read the stored record. Stated there rather than listed as a defect.

## Deliberately not done

- **No GitHub Security Advisory** for the offline credential cache: it is a design change disclosed in the note, not a defect in a shipped version.
- **Nightly installs poisoned before #219 are not auto-healed.** Nightlies from 2026-09-19 to 2026-09-23 could persist the account holder's per-server token over a seated managed or Home-member profile (the admin gate lost in `235e5199`, restored in `65098517`). No stable release ever carried that regression, and the nightly is a separate app id (`com.beb.plxnative.nightly`), so a stable 0.6.x → 0.7.0 upgrade cannot inherit it. A heal was tried and dropped because it cannot tell a poisoned record from a Home member legitimately signed in with their own account; the recovery is switching profile away and back.
- **No downgrade path.** A 0.7 record read by a 0.6 build is not supported, and the note says so.
- **`docs/known-issues.md`'s single entry was not rewritten here.** It still describes the k5lp Load-race fix as possibly missing from `main`; the fix is present on this tree (`src/starfish.c`'s `LOAD_RETURNED` gate and `webos.rs`'s `rtkmem` probe). Left for a docs change, not a release document.

## Release configuration

| | |
|---|---|
| flavour | `com.beb.plxnative` (stable) — the id users install; `FLAVOR: stable` is pinned in the release workflow's build job |
| cargo features | `RELEASE=1`, which drops `devtools` and `devtriggers` |
| built by | GitHub Actions, from the tag, at a path identical on every runner |
| toolchain | webOS NDK unchanged since v0.6.0, with the NDK's `libglibc_polyfills.a` now excluded from every link; Rust nightly pinned by date in the `RUST_NIGHTLY` repository variable |

What is unusual about this build, relative to v0.6.0:

- **Licence.** First-party code moved from MIT to GPL-3.0-or-later (`d1f68d90`); the historical MIT grant is kept in `licenses/PlxNative-historical-MIT.txt`. The release now attaches the program's own corresponding-source archive (`plxnative-source-*.tar.gz`, built by `ci/make-source-bundle.py`) and `source-rebuild.json`, beside the FFmpeg tarball and `build-ffmpeg.sh` it always carried.
- **`getauxval`.** The NDK polyfill archive is replaced by `src/compat/getauxval.c`; `ci/check-link-evidence.py` and `ci/check-packaged-elf.py` prove no packaged ELF carries the old archive. The generated half's `DT_NEEDED` and firmware matrix are the evidence that this changed nothing at load time.
- **Storage helper.** The `plxnative-storage` helper and its private DB8 kind, which shipped on the 0.6 line from v0.6.6, are new relative to v0.6.0 on this line. Its install identities were corrected in #197.
- **Sentry Native** is pinned at 0.16.6 (`21675eb2`).
- **One new on-device IPC read.** At boot, off the main thread, the app reads configd's `tv.config.supportDolbyHDRContents` over its existing anonymous LS2 client (#215). No new network host was identified by a source grep; the generated host-string table is the measurement.
- **Bundled FFmpeg links the system zlib** (#235). `ci/build-ffmpeg.sh` now passes `--enable-zlib`, so the bundled `libavformat` gains a `DT_NEEDED` on `libz.so.1`. The main binary's own `DT_NEEDED` list (`ci/expected-dt-needed.txt`) is unchanged, since the FFmpeg libraries are loaded at run time. `libz.so.1` is present in every firmware image in `tools/fwcompat.py`'s database: `libz.so.1` and the four symbols `libavformat` imports from it (`inflate`, `inflateEnd`, `inflateInit_`, `uncompress`, all unversioned) resolve in every image from platform release 1.2.0 to 11.2.0 (zlib 1.2.7 to 1.3.1), read with `tools/fwcompat.py --lib libz.so.1` against this build's `libavformat-plx.so.63`. `webosbrew-ipk-verify`, which grades the whole package, runs in the release workflow. The demuxer's zlib support also enables compressed-`moov` MP4 and compressed ID3 tags, newly supported rather than changed.
