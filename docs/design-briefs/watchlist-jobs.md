## Boundary and invariants

W1 already captures the seated `CurrentProfile` and `WatchlistAuth` in `WatchlistInput`; keep that contract, including no account on Open and the profile id, uuid and generation check. The store owns the rows, `IntentLedger`, match table, view state, claims, retry counters, outbox and epoch. The app owns roster/profile/date capture, job admission, registry lookup and worker scheduling. The existing `StoreRunner`, `Job`, `Addr`, `Port`, `StoreId::Watchlist` and `landgate` are the runtime; do not add a second executor, tape, global injection slot, or production/test `cfg` fork.

A step or view may neither read `LiveIo`, the process registry nor the wall clock. Account transport stays off-frame and receives the captured credential. PMS lookup is through `KeyedClients` constructed by the app from the job's `ClientKeys` snapshot and host `client_for` function; it rechecks instance, token and grant when each request is built. A changed key is unanswered, not an empty server answer. This does not retract a request already on the wire. Never log credentials, GUIDs, rating keys or titles. Preserve the existing plex Watchlist write guard, including its discover stand-in and live-switch rules; tests must never write to a real account or create the live switch.

## Inputs at every decision and capture

Proposed borrowed input (names may follow local conventions):

```rust
pub struct WatchlistFacts<'a> {
    pub keys: &'a ClientKeys,
    pub today: Option<&'a str>, // caller-captured UTC YYYY-MM-DD; None if unavailable
}
```

The Bridge refills keys and captures the date once per relevant call, then passes the same input through the entire call: `pump_with_gate(gate, profile, facts)`, command paths that can rederive, `notify_map`/`rematch_on`, view and feed capture, `held_keys`/`held_copy`/`copy_of`, and `art_server`. Update all transitive callers, including immutable capture/held paths; if an immutable Bridge entry cannot refill, change its caller to capture and hand the facts in, not to reuse a stale or ambient registry. Date conversion remains pure and the app reads the clock. Carry `None` faithfully; do not synthesize a date. A capture must not hand out references beyond the snapshot's lifetime; materialized views retain values, not a borrowed mutable Bridge.

Implement `Reach` as a pure adapter over `ClientKeys`: roster from `slots()` in captured order; reachable only when captured `facts(sid).source` has `Some(Outcome::Reachable)`; missing/incoherent source is not reachable; rank current server first, then described `owned`, then shared/unknown, preserving existing tie/order behavior. Use `keys.current()`, `roster_gen()` and `facts_gen()`, and never infer a current or owned server from a key-only fixture. `match_rows`, matched-known selection, tile derivation, released fallback, and art/copy selection use these same captured semantics. Missing date/release remains Unknown as today. Every list/rematch/delta job owns a clone of the captured keys used for both its roster and its generation; roster changes during a worker cause the next pump to see the mismatch and rematch, rather than attaching a fresh generation to old answers. Capture the date used for each landing/derivation on the consuming pass, not an ambient worker clock. Verify whether a date rollover needs a rederive trigger: preserve existing observable behavior unless a separately approved change is needed.

## Typed jobs, addresses and ownership

Add five distinct `StoreJob` variants with `Job<Req>` and typed ports, wired to `store()`, `take_jobs_of`, `has_jobs_of`, live and held `StoreRunner` arms. Each job's address and `Tag { profile_gen, epoch, req }` travel in every post/terminal. `req` is allocated for **every** claim, including resolves; track the active request per lane and per `(sid, rk)` resolve. Validate address, epoch, profile and the exact request for its own claim before applying state, never compare a write against the latest unrelated list/resolve request. A retired port cannot settle a new claim even if a key is reused. Resolve may run without an account: capture the current profile generation and epoch independently of `auth`, and fence it on profile change/reset as well. Keep identity values out of Debug.

| Kind | Owned request values | Posts | Exactly one terminal |
|---|---|---|---|
| Write | tag, captured auth, `PendingWrite` (hex, intent, stamp) | none | `Written { write, outcome }` or `NotStarted { write }` |
| List | tag, auth, keys, `known` GUID set and its roster generation, page-zero ETag, read stamp/write snapshot as store claim state | page, page failure, not-modified, released set, in order | `ListDone`, `NotStarted`, or `Panicked` |
| Rematch | tag, keys, full `(guid, Kind)` rows | `Rematch { answers, roster_gen }` | done, not-started, or panicked |
| Delta | tag, keys, sid, deduplicated `(guid, Kind)` asks and notification debt identity | `Delta { answers }` | done, not-started, or panicked |
| Resolve | tag, keys, sid and rating key | none | answered `Option<Option<hex>>`, not-started, or panicked |

Use `Addr { to: MachineId::Store(StoreId::Watchlist.ord()), req: RequestId(...) }`, with `Tag.req` matching that request and a checked, non-reused allocation for the lifetime of potentially retained ports; epoch/profile remain additional fences. Concrete boundary: `enum WatchlistStreamEvent { Page(..), PageFailed(..), NotModified, Released(..), Rematch(..), Delta(..) }`; `enum StreamEnd { Done, NotStarted, Panicked, Cancelled }`; `WatchlistStreamPort::post(addr, tag, event)` and `Port<StreamEnd>::done(addr, end)` / `refused(addr)`; `Port<WriteEnd>` and `Port<ResolveEnd>` answer the two one-shot jobs. The port binds the immutable tag at creation and validates the supplied address; where `Port::done` has no tag parameter, the bound tag accompanies the terminal in its mailbox. `ListDone` is the list's `Done` terminal and is applied once, not also posted as an event. Resolve results include sid/rk in the bound request. `refused` maps only to `NotStarted`. Exact type names can change during implementation, not these shapes or guarantees.

Ports expose an ordered `post(addr, tag, event)` and an idempotent terminal operation for streams; after the first terminal, reject further posts/terminals. Writes and resolves are one-answer ports with the same first-terminal rule. Keep per-attempt messages and terminal ordered even when drained separately; terminal must not overtake a page or an inline admission refusal. Store/port locking atomically couples terminal publication with claim completion so a pump cannot observe idle before the last post is visible. Wake idle after each accepted post or terminal. Terminal publication is guaranteed in a `catch_unwind`/RAII boundary outside the fallible body, including panic during account transport, lookup, decoding or producer code; no panic path may merely drop a flag. If the consumer reset/cancelled, the retired port still completes exactly once but its landing cannot mutate the new epoch.

`NotStarted` means strictly no worker body ran and no request could have reached the wire (missing/stale key before admission where applicable, admission refusal, or cancelled while still parked). A started write panic/error is `Failed`, never `NotStarted`: it may have reached the account. For a refused write requeue the exact `PendingWrite` through `IntentLedger::requeue`, preserve press order/coalescing and set `write_retry = 120`; no other write overtakes it. The decrement/eligibility order and exact retry pump must match the current 120-pump behavior. `writes_seen` and ETag invalidation at claim remain conservative as today, even on refusal; `Landed` and `Failed` retain current optimistic ledger/reread behavior.

List refusal retains `list_wanted`, clears the claim, and applies the current 120-pump list retry; it is not a page error. Rematch refusal likewise clears its lane and backs off; the unchanged roster mismatch retries. Delta refusal must restore its exact notification obligation as described below. Resolve refusal, missing/stale client or panic clears `resolving` without caching, so a later menu can ask again; a successful nonportable GUID is cached as `Some(None)`, while an unanswered PMS is outer `None` and is not cached. A panic in list produces an addressed failure followed by one terminal, disqualifies the in-progress read's validator, and unwinds a partial incoming reread without committing it; retain the previous complete list's ETag and rows on a failed reread, and preserve already displayed first-load pages/truncation rather than publishing an incomplete reread as complete. Rematch/delta panic retains the prior match table; it still terminates and releases its claim. Avoid silently dropping a delta on panic: return its still-owed notification debt for a bounded retry.

On reset/profile change, retire the old mailbox and outbox claims; discard queued work that has not started and its retired settlements, signal any supported cooperative cancellation, and fence all old results. Use a per-claim shared admission state with an atomic transition `Queued -> Started` or `Queued -> Cancelled`: the owner cancels the queued state on retirement, and the runner must win `Queued -> Started` before spawning/doing IO; if spawn itself refuses, it publishes `NotStarted`. This capability is not a read of mutable store state from a worker. A parked job released after cancellation cannot start. Once `Started` wins, cancellation is cooperative and cannot say no IO occurred. Do not claim that cancellation undoes a started account write or automatically retry it under the next profile. A started write never publishes `NotStarted` or an early cancellation that would permit a second write while its outcome is unknown: it publishes `Written(Landed|Failed)` on return/panic; a reset retires its old claim without waiting on it or launching it under another profile. For a started read, whichever of completion/cooperative cancellation wins publishes the sole terminal, suppressing later posts. Scope cancellation per claim, not a shared global token.

## Landing, owed and notification fan-out

Preserve `StoreId::Watchlist` and existing landing gate/replay behavior. The owner claims before outbox emission. Maintain per-request outstanding state across drain calls: pages alone do not discharge a stream; one accepted terminal does. For the two existing gated mailbox families, the `take_landings_owed` predicate must count outstanding list/rematch/delta/write terminals and each resolving terminal, including terminal-only refusal/panic/cancel; aggregate already-drained progress instead of comparing only a single take's event count with all claims. A stale terminal settles only its own retired claim and cannot unblock or clear a current one. Do not block the main thread on live workers outside the existing gate; dump/armed replay waits only on actual owed claims, and a terminal always makes progress. Do not count merely emitted/parked work as complete. A refused admission is an observable addressed settlement and must be delivered before a gate could wait for it. Tests must exercise normal, dump and held/inline runner paths and demonstrate that every terminal/refusal/panic makes the owed predicate false exactly once.

`Bridge::watchlist_pump` captures profile, keys and date, steps, then drains Watchlist jobs **in that same call**. Add Watchlist to `Stores::NOTIFY_FILLS`; `Bridge::notify_pump_captured` must drain it in the same fan-out call after `notify_map`, alongside existing Browse/Hubs, not at the late-job backstop. Wire all other entry points that can emit a Watchlist job to an immediate drain. Preserve the existing per-connection Notify admission/settlement ordering and do not add Watchlist work before Notify has produced its map.

`spend_library_owed` currently removes a debt only if `rematch_on` really starts, and spaces subsequent work only then. Outbox emission alone cannot prove admission. Change it to reserve the exact `(sid, kind, owe)` and ask snapshot under the delta request id without losing concurrently arriving `added`, `gone`, or `sweep` debt. Settle admission in the originating Bridge call for a live runner, before the fan-out returns: on actual admission mark the reserved debt spent and apply the existing nonempty spacing once; on `NotStarted`, restore/merge it and do not mark spent. A held job stays reserved, not spent, until its real admission or refusal; completion and later notifications merge independently, so neither is erased. Expose an addressed admission outcome separate from the sole stream terminal if necessary; it is not itself a terminal and must be ordered before one. For panic after start, re-owe the reserved affected asks without undoing later notifications; apply a bounded retry to avoid a hot loop. Empty asks or an unreachable captured sid retain the current `rematch_on == true` no-worker semantics and existing spacing rules. Preserve `read_in_flight` semantics: an emitted, parked, or active list/rematch/delta counts as in flight until its terminal; changes that arrive while it is out remain owed.

## Wire behavior and test matrix

* Keep page-zero `If-None-Match`, 304 plus released fetch, raw wire-count advancement, no page-count cap, page-0/released/later-page ordering and one terminal. An initial later-page failure leaves visible partial rows truncated; a reread failure keeps the previous complete rows and validator. Only a complete quiet read stores its ETag; any write invalidates it, including a write overtaking the read. `NotModified` does not suppress released refresh.
* Unit-test every job's payload, address and exact tag; mixed list/write/resolve request IDs; stale profile, reset, duplicated or late posts/terminals; same key reused in a new epoch; no-auth resolves; retired parked work; and only-one terminal under completion/cancellation races. Check a stale worker cannot affect the new profile, and account writes never use a new profile's credential.
* Script transport via explicit per-test runner/account and PMS ports, not an ambient mocked registry or test-only production branch. Exercise real worker body/port with inert local fakes and production runner admission separately; assert write guard refuses unarmed live writes without issuing a network request. No real-account writes, no live-switch file. Exercise both worker panic and spawn/admission refusal for all five kinds, including after a partial list page and before/after resolve response.
* Test `NotStarted` vs started `Failed`, 120-pump retry boundary, FIFO/coalescing with two IDs and changes while refused, write overtaking list, reread owed once, list/rematch backoff, resolve unanswered vs nonportable result, no hot resend, and exact once release of list/write/resolve claims.
* Drive notify-map created/deleted/sweep and resync while a read is in flight; assert delta starts in the originating `notify_pump` with zero late jobs, and refusal/held/stale-key/panic restores only its own debt, preserves simultaneous new debt and spacing, and eventually retries. Verify empty/unreachable paths, retained match table, partial server replies and `GUIDS_PER_REQUEST` chunking: unanswered is not `Absent`.
* Hand distinct `ClientKeys`/dates to pump, feed/capture, `held_keys`, `held_copy`, `art_server` and notify paths; test current > owned > shared, missing/incoherent evidence, reachability/facts generation changes, changed roster while a list is running, midnight/unavailable date and captured-vs-live key races. Include key retoken/revoke after capture, and a profile reset while parked/on wire. No registry fallback in tests.
* Arm the actual dump/replay gate and force terminal-only refusal, panic and cancellation for each family; observe termination, ordered partial posts, no stranded busy flag and no double settlement. Preserve recorded landing ordering/frame semantics; compare inline, held and live scheduling. Existing watchlist, notification and Bridge wiring tests stay green; add targeted store, runner, Bridge/fan-out, gate and feature-set tests before broad gates.
