## SAME-CALL protocol: connection cursor, not bulk two-pump

Choose a minimal split of the existing per-connection loop. A bulk begin-all/start-all/drain-all changes when earlier connections' ordinary mail is observed; reject it. A second `pump()` changes frame and retry/stability accounting; reject it. The following named pure entry points are the implementation contract:

1. `Stores::notify_begin(&NotifyInput)->NotifyPass`: increment frame ONCE; reconcile once; capture frame and initial connection count/cursor in a private pass token; initialize NotifyOut. No network mailbox is taken. Armed/disabled applies the explicit per-conn stand-down transitions above before returning an empty completed pass, without taking orphan mail or emitting jobs. Preserve identity/roster reconciliation rules; close_all alone is insufficient. Do not expose a replay landing.
2. `notify_prepare_next(&mut pass, &NotifyInput)->Option<NotifyTurn>` visits exactly the next conn. Perform its existing key/gate/drop/due logic. For due launch create fresh Link, retain pending incarnation and emit ONE NotifyStream job. Turn holds conn identity/Addr/frame, not a borrowed Client. Existing live conn emits no job. No attempts/backoff is changed speculatively for an attempted launch.
3. Exit data step. Bridge drains **only StoreId::Notify** immediately through existing `take_jobs_of` -> `start_jobs` -> `StoreRunner::start`. Runner synchronously reports addressed admission to a separate Link admission slot (not ordinary Inbox end), carrying the originating frame captured when emitted. Accepted means successfully scheduled OR deliberately held, not first SSE data. At INITIAL admission only, false launcher means work was never executed; key/gate mismatch rejects with NotStarted and prelaunch cancel settles Cancelled once. Initial rejection is settled before this conn's ordinary drain. Deliberately held acceptance is final single assignment: RELEASE is a distinct execution stage, not another admission. On release key/gate/OS-launch failure, deliver one ordinary terminal (NotStarted, retryable like Transport/status zero) to the accepted Link; never rewrite admission or reuse origin_frame. Owned current-conn drain backs off at observation frame. Cancelled/orphaned release terminalizes only its old port once and never touches any replacement/store state. The accepted receipt is not a terminal. Admission slot cannot be overwritten. Implement the receipt as Notify-local Link metadata read by the next pure entry, preserving `start`'s existing void API; no callback or new application runtime.
4. `notify_settle_admission(&mut pass, turn)` consumes only that turn's addressed admission. On accepted install/commit Connecting. On false reproduce `back_off(origin_frame)` NOW, drop pending Link, and consume the local NotStarted terminal so it cannot cause a second backoff. Prelaunch cancel of an already orphaned incarnation has no store effect. This occurs before ANY ordinary drain for that conn. Never read ordinary worker terminal to infer admission: an accepted worker can complete before `start` returns.
5. `notify_finish_turn(&mut pass, turn)` takes that conn's ordinary events/end once under its inbox lock, running existing `Conn::drain(pass.frame)` ordering and stability exactly once. Release input fence requires same incarnation/Addr/full key and allowed owned evidence; a lifecycle/profile change invalidates turn and discards mail. Advance cursor only here. Repeat 2-5 for next conn. No retry decrement or frame increment in settlement/finish.
6. `notify_end(pass)->NotifyOut` asserts every turn settled/drained; Bridge invokes notify_map ONCE on completed output, then drains NOTIFY_FILLS immediately before returning existing `(resynced, endpoints)`.

Admission origin_frame can be private Link emission metadata rather than added to NotifyStreamReq: INITIAL admission rejection returns its captured Addr+frame, never reads a later store frame; an accepted-held RELEASE failure instead uses ordinary terminal observation frame. Generic start_store_jobs_of(Notify) can schedule a manually emitted job, but cannot finish a pass: each real caller must use the cursor driver; aggregate backstop remains an error signal, not an alternative delayed implementation.

Ordering example: conn A old live mail, B refused launch, C accepted fast worker. A is prepared/drained before B is launched; B backs off using F before B drain; C then launches and drains at F. If worker B/C posts asynchronously before its own lock-take it is eligible this call, just as old connect-before-drain; after lock-take it waits for next frame. An A post arriving while C launches waits for next frame, not scooped up by a final aggregate drain. Within each Link posts before terminal are ordered by the same mutex. Across connections retained table order, not admission receipt arrival or network completion order, controls NotifyOut arrays. This is source-equivalent to `notify.rs:408-419` with IO extracted between pure phases, not a one-pump marker. Same-call refers to admission; ordinary network completion remains observed at the original connection drain point, never eagerly at runner start.

## Terminal ownership and orphan discipline

Harden existing Inbox in place with `terminal_sent: bool` that persists after `end.take()`. Under one mutex: post ignores terminal_sent; finish checks it, sets it and queues exactly one terminal, preserving previously queued posts. Never use `end.is_none()` as permission to finish again. A separate admission slot is single assignment, independent of terminal state: a fast accepted worker may finish before its accepted receipt is stored. `Port::refused` atomically commits NotStarted once; launch false promises closure never ran. No refusal enters recorded src_result, tape or landgate mailbox.

Store cancellation sets cancel and finishes Cancelled once on the old Link, then forgets it. Worker completion racing cancellation loses harmlessly to terminal_sent; later pushes ignored. Orphan means old Conn no longer owns the Link: nothing from that Link (including terminal/admission) can land in a replacement Conn. Drop/reset closes all. Suspended/armed/removed/profile-reset incarnations are not owed; held-cancel is pruned/terminally settled without dialing. INITIAL prelaunch key/gate mismatch or launcher false: NotStarted plus rejected admission, backoff once at originating frame before drain. AFTER accepted-held admission, release key/gate mismatch or launcher false: one ordinary NotStarted terminal, admission remains accepted, and backoff once at observation frame only if this exact Addr/full-key incarnation still owns the Link. This follows existing ordinary retry semantics without resetting attempts on accepted/held/released scheduling; only existing identity replacement, stability, resume and network rules reset attempts. If gate/key reconciliation has already retired the Link, discard its terminal without attempts, retry, gap or resync changes to any newer/orphan connection. Accepted worker panic: Transport terminal, ordinary drain at observation frame. Actual accepted cancel: Cancelled once, with existing current-conn terminal semantics if still owned; deliberate lifecycle cancellation already removes ownership and clears gap where specified. Transport status zero remains ordinary retry, not Session park.

No new reserving Fetch or landgate claim is needed: Conn's pending/Connecting/Live incarnation is the local claim. End/refusal/cancel retires it exactly once; stale/orphan has no owed bit. Armed path cannot retain an indefinite stream owed predicate, so dump never waits for SSE termination. Keep S7 many-post/one-terminal/cancel vocabulary; `machine/src/job.rs:53-58` only supplies terminal Port, not a shared stream implementation. Do not genericize all ports/channels now. Watchlist W2 can extract the proven minimal shared channel when its second concrete consumer lands.
