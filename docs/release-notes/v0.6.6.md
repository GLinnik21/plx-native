# v0.6.6 — sign-in that stays put

This maintenance release gives sign-in and reporting settings a reliable app-owned home, keeps saving work from pausing the screen, and prevents backgrounded windows from continuing to present frames.

## When updating: install over your existing app

Install v0.6.6 over the existing PlxNative app. Do not uninstall it or choose **Delete all local data** first: on its first start, PlxNative automatically imports the existing v0.6 sign-in and reporting choices into the new stored format.

This is a forward migration only. Downgrading, uninstalling and reinstalling, or clearing local data is not guaranteed to preserve or recover the migrated records.

## What's new

- **Sign-in and reporting choices now use app-owned storage.** Existing v0.6 data is imported on first start, and signing out prevents an older copy from bringing the account back.
- **Saving no longer pauses ordinary navigation.** Account and setting changes are queued in the background; if a save cannot be confirmed, the app keeps the failure visible and offers Retry.

## Fixed

- **Sign-in now persists on sets that denied writes to the old application path.** The packaged state directory uses the writable ownership required by native webOS apps; see the update instructions above so the existing session can be migrated.
- **A backgrounded app no longer keeps uploading or presenting UI frames.** PlxNative closes the presentation gate during both startup and normal use, then reacquires its native window state before drawing after foregrounding.

## Compatibility

The v0.6.6 package-upgrade and device gates are still pending during release preparation. Earlier field and development runs establish the problem and the individual fixes, but they do not count as a run of the current release candidate; the final evidence belongs in the [technical audit](https://github.com/GLinnik21/plx-native/blob/release/v0.6/docs/release-audits/v0.6.6.md).

## Known issues

- **The automatic migration has not yet been exercised by installing the current candidate over an existing app on a television.** Host fixtures cover every published v0.6 record shape, but they cannot establish package preservation or the television's key service.
- **IPv6 addresses already present in older event logs or shared copies are not rewritten.** v0.6.5 stopped those addresses appearing in newly written lines; review or remove older copies where appropriate.
- **The rooted sandbox Repair button and experimental non-root procedure still lack an affected-device run through the app.** Their limits and recovery path remain as documented for v0.6.5.
- **The original one-off libmali crash remains unresolved.** The background rendering change is defensive and adds lifecycle evidence; it does not establish that the reported crash had this cause.

## Installing

Download **com.beb.plxnative_0.6.6_arm.ipk** and install it with the [Homebrew Channel](https://github.com/webosbrew/webos-homebrew-channel) or [dev-manager-desktop](https://github.com/webosbrew/dev-manager-desktop). You do **not** need a rooted TV.

Nothing in this distribution chain is signed, so this sha256 is what tells you the file you have is the file published here:

```
__IPK_SHA256__  com.beb.plxnative_0.6.6_arm.ipk
```

[Installing and checking a download](https://github.com/GLinnik21/plx-native/blob/release/v0.6/docs/install-and-verify.md) covers the other assets, how to check the hash on each platform, and the Developer Mode expiry that uninstalls your apps. This package bundles FFmpeg under LGPL-2.1-or-later and its complete corresponding source is attached to this release. Exactly what was built, verified and shipped is in the [technical audit for v0.6.6](https://github.com/GLinnik21/plx-native/blob/release/v0.6/docs/release-audits/v0.6.6.md).
