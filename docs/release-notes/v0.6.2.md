# v0.6.2 — staying signed in on 2024 and newer LG sets

This release fixes one reported problem: on 2024 and newer LG televisions the app forgot its sign-in. You scanned the code or entered the PIN, the app worked for that session, then the account menu said "Sign in" again and the next launch was back at the QR code. No action required — this update installs the same way every other one does. It will ask the reporting question again once on first launch, for the reason explained under Changed.

## Fixed

- **The sign-in now survives a relaunch on 2024 and newer sets.** On those televisions the app stores the sign-in through the set's own key service, and on the reported sets that service sealed the sign-in but could not open it again — so every later read looked like no sign-in at all, and the wait for that service is also why the sign-in screen took so long and looped through "try again" first. The app now checks that the key service can open what it has just sealed before trusting it at all, keeps one working copy for the session, and, when a stored sign-in cannot be opened, replaces it after your next sign-in with the same owner-only file every older set uses, and stays on that file until you sign out. Reported on an OLED55C41LA (a 2024 model, platform release 9.2.2) in [issue #75](https://github.com/GLinnik21/plx-native/issues/75) and on an OLED77G45LW (platform release 11.2.0) in [issue #76](https://github.com/GLinnik21/plx-native/issues/76). Neither set is available to the maintainer, so please see Help test this release.

## Changed

- **Opt-in reporting can now say how your sign-in is stored.** If you have switched on usage reporting, every report carries one more fixed-vocabulary value: whether the sign-in is stored in the plain owner-only file, through the key service, or was refused by it. If you have switched on error reporting, a failure to seal or open the stored sign-in is reported as a handled event naming the step that failed and the numeric error the key service answered with. Never the sign-in itself, never any key material, never a file path. The full list is in [PRIVACY.md](https://github.com/GLinnik21/plx-native/blob/release/v0.6/PRIVACY.md). Nothing is sent unless you opted in.
- **Existing installs are asked the crash/usage reporting question once more, on first launch of 0.6.2.** The privacy notice gained the storage facts above, so the policy version behind the question changed, and this project's rule is that a changed policy is asked again rather than having a previous answer silently carried forward. The question now says why it is being asked again. Nothing is sent before you answer.

## Compatibility

- **Plays video, verified by watching it — 2019 LG sets.** One television: an LG 49SM9000PLA, which reports platform release 4.10.2 (LG markets this generation as webOS 4.5).
- **Plays video, reported by someone else — one 2021 set.** [mariotaku](https://github.com/mariotaku) of webosbrew ran v0.2.1 on an LG 65UP7560AUD (platform release 6.5.2) on 2026-08-11 and got a picture: [issue #22](https://github.com/GLinnik21/plx-native/issues/22). Six of eight attempts played. That report has not been repeated on this version.
- **Starts, and nothing further is known — every other firmware from webOS 4.0 up.** The loader resolves this binary's libraries and symbols cleanly against every firmware image webosbrew has at 4.0 or newer. That grades startup and says nothing at all about whether video plays; the matrix is in the [technical audit](https://github.com/GLinnik21/plx-native/blob/release/v0.6/docs/release-audits/v0.6.2.md).
- **Does not start — webOS 3.9.2 and older.** Symbols the app needs are missing from those firmwares, so the process is killed before anything appears.

## Help test this release

The fix above was built and tested on a television that has no key service of its own, so it has not been run on the sets it is for. If you have a 2024 or newer LG set: install this version, sign in once, close the app and launch it again. If the account menu still shows your account, that is the report we need — say so in [issue #76](https://github.com/GLinnik21/plx-native/issues/76). If it does not, switch on error reporting when asked and sign in once more, and the report that sends is the one that will tell us why.

## Installing

Download **com.beb.plxnative_0.6.2_arm.ipk** and install it with the [Homebrew Channel](https://github.com/webosbrew/webos-homebrew-channel) or [dev-manager-desktop](https://github.com/webosbrew/dev-manager-desktop). You do **not** need a rooted TV.

Nothing in this distribution chain is signed, so this sha256 is what tells you the file you have is the file published here:

```
__IPK_SHA256__  com.beb.plxnative_0.6.2_arm.ipk
```

[Installing and checking a download](https://github.com/GLinnik21/plx-native/blob/main/docs/install-and-verify.md) covers the other assets, how to check the hash on each platform, and the Developer Mode expiry that uninstalls your apps. This package bundles FFmpeg under LGPL-2.1-or-later and its complete corresponding source is attached to this release. Exactly what was built, verified and shipped is in the [technical audit for v0.6.2](https://github.com/GLinnik21/plx-native/blob/release/v0.6/docs/release-audits/v0.6.2.md).
