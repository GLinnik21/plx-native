This release exists to make a bug report possible. Playback still fails on webOS 5 and newer, and
nobody working on this owns such a television — so v0.2.1 adds an on-screen diagnostics read-out you
can photograph, and fixes the two ways the app used to fail with no message at all.

## Stats for nerds

During playback, press **…** on the transport (the third round button, beside Subtitles and Audio)
and tick **Stats for nerds**. A panel appears in the top-left corner showing what the app is
actually doing: which video-plane mechanism this firmware uses, how far the pipeline got, whether
the demuxer produced anything, what was fed to the decoder and whether it was accepted, HTTP status
and bytes received, the codec chain from your file through the server to what we told the decoder,
and sixteen seconds of feed-rate history.

It stays up while you watch, takes no buttons, and is turned off by unticking the same box.
Untick it, or leave it — it does not affect playback.

**If playback fails, a photograph of that panel is the whole bug report.** It deliberately contains
no server name, no address, no account details and no media title, so it is safe to post publicly.

## Two silent failures now say what happened

Both used to leave a spinner on screen forever with nothing in the log:

- A demuxer that opened the stream and produced no frames now reports a playback error.
- A `Load` the TV's media pipeline **refused** now reports one too, instead of waiting for a
  completion callback that can never arrive.

## Fixed

- **The event log printed credentials.** A transcode URL ends in your Plex token, and one log line
  included the whole URL — reached by an ordinary audio-track switch. The sign-in flow logged the
  PIN id, which is what redeems an account token. Both removed, and every line now passes a scrub
  on the way out, so a future mistake of the same shape cannot reach the file. **If you have sent
  anyone a `/tmp/plxnative-events.log` from an earlier version, rotate your Plex token.**
- **The exported window was told a 4K stream was 1080p** on webOS 5+, so the video plane was set up
  for the wrong source size.
- The transport's controls were unreachable in exactly the state worth reporting: with playback
  stuck buffering and the on-screen controls timed out, the app treated them as hidden while still
  drawing them, so focus could never reach the buttons — including the new **…**.

## Installing

Grab the `.ipk` and install it with the [Homebrew
Channel](https://github.com/webosbrew/webos-homebrew-channel) or
[dev-manager-desktop](https://github.com/webosbrew/dev-manager-desktop). No rooted TV needed.

Nothing in this distribution chain is signed, so the hash is the only thing between you and a
tampered package:

```
019b4e1405afb8cea88d99c7da5125e0bc9888294a71297938536309801a5ca3  com.beb.plxnative_0.2.1_arm.ipk
```

**Correction (added after publishing):** this release originally claimed the build is
reproducible. It is not yet, and you should not rely on rebuilding to check the hash. Two builds of
the same commit *in the same directory* are byte-identical, but the bundled FFmpeg records its own
build path inside the `.so` files, so a build from anywhere else differs — the published libraries
carry the maintainer's build directory. Being fixed; until then the sha256 above is the only check,
and it is the one the Homebrew Channel verifies at install.

## Source for the bundled FFmpeg

`ffmpeg-9.0.tar.xz` and `build-ffmpeg.sh` are attached. FFmpeg is LGPL-2.1 and shipping it makes
that our obligation: the tarball is unmodified upstream, the script carries the complete configure
invocation that produced the libraries, and they are separate `.so` files you can replace with your
own build. Details in `THIRD-PARTY-NOTICES.md`, inside the package.

## Still the same scope

Movies and TV shows from a Plex Media Server on your local network. Playback is device-verified only
on webOS 4.10. No music, photos, live TV or DVR.
