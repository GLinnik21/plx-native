# v0.6.0 — a failure screen that names your television, and two reports you choose to send

Until now, a television that refused to start a video sat on a black screen with nothing to show for it. This release turns that refusal into a failure screen naming your set and the reason, changes what the app asks a television to decode so fewer refusals happen in the first place, and adds two reports — crash details and product analytics — that stay off unless you turn them on.

## If a PIN protects a profile on your television: install this one

**A second way to reach a PIN-protected profile with no PIN.** From inside an already-open protected profile, pressing *Change profile* and then BACK returned you straight back into that profile with no PIN asked — instead of the picker you had just opened. The first way to do this, at the television's boot picker, was closed in v0.4.0; this is a different control, and it stayed permissive on the reasoning that whoever opened *Change profile* is already signed in as that profile — true of the person who pressed it, and false of whoever is holding the remote by the time BACK is pressed.

**v0.1.0 through v0.5.0 are all affected. This release is not.** Nothing left the television and no credential was exposed to anyone off it — a profile's own per-server token stays exactly where it always was; what was wrong is which screen BACK could walk back into. In the ordinary Plex Home arrangement the protected profile is the adult's, so this handed a child the adult's library, its watch history and its unrestricted content, once the adult had signed in and stepped away.

**What to do:** install this release. There is nothing to rotate and nothing to sign out of, and your profiles and PINs on plex.tv were never involved.

**What is fixed, and what is not:** BACK from *Change profile* no longer resumes any profile — it always raises the picker with nothing behind it, protected or not. One narrower gap is unchanged by this release: restarting the app on a television whose roster holds only one profile still opens that profile directly without asking for its PIN, because a roster of one has nothing for a picker to offer instead. A household relying on a PIN should keep more than one profile on the roster. Plex's own parental controls are the server's and are untouched by any of this.

## Two optional reports, off until you turn them on

**Crash and error reports** (sent to Sentry, in Germany) and **product analytics** (sent to PostHog, in Germany) are two separate choices. Both start off, whether this is a fresh install or an update, and stay off until you answer the question the app asks at first sign-in or change your mind later in Settings → Privacy & data.

Turning a category on mints it a random identifier. The Crash report ID exists so a problem that reached many installations can be told apart from one installation that hit it many times. The Analytics ID exists so your own product analytics events can be grouped as one install's activity. Neither identifier is derived from your Plex account, your television, or anything about you, and the two are never linked to each other.

Turning a category off, or signing out, deletes its identifier on this television along with any report still waiting to be sent. One report the sender had already picked up at that moment may still complete; nothing further goes out after it.

Neither report can carry a media title, a Plex account or profile name, a search, a server name or address, an access token, subtitle text, or your exact viewing history. Settings → Privacy & data shows the exact fields a report of each kind can carry before you decide, and the full account is in [the privacy policy](https://github.com/GLinnik21/plx-native/blob/main/PRIVACY.md).

## What's new

- **Optional crash and usage reports.** See above — off until you choose to turn them on, in Settings → Privacy & data or at first sign-in.
- **A Settings screen that tells the truth about what this television keeps.** Sign-out, Delete all local data, both reporting choices with their identifiers and example payloads, and the full in-app privacy and legal text now live in one place reachable from Home. The privacy text itself is corrected: it used to claim a resume bookmark the app does not keep, and omitted recent searches, per-server tokens and addresses, the reporting choices themselves, and what survives an uninstall.
- **Credentials get stronger protection where the television offers it.** On a set that exposes LG's Key Manager service, your Plex account token and per-server tokens are now encrypted with a key held by the television rather than stored as plain JSON; a set without that service keeps the same permissions-restricted file this app has always used.
- **About PlxNative names the exact build, not just the version.** Every developer build between two releases reports the same version number, so the About screen now also shows the commit it was built from.

## Fixed

- **A PIN-protected profile can no longer be reached with no PIN.** See "If a PIN protects a profile on your television" above.
- **A refused Load no longer leaves you on a black, indefinitely "Connecting" screen.** When the television refuses to start decoding before showing any picture, playback now ends in a proper failure screen instead of an infinite spinner. That screen carries a support footer — app version, webOS release, television model and board, and a failure code — so a photograph of it is enough to report from. If you filed [issue #63](https://github.com/GLinnik21/plx-native/issues/63) or hit something like it, see "Help test this release" below.
- **For H.264 playback, the app now asks your television for closer to what the stream actually needs**, instead of always asking for a 4K/60 decode path regardless of the file's own size or frame rate. On the developer's own television, a 24-frame-per-second 4K file that used to be presented at roughly 13 frames a second under the old blanket request is presented at its real rate now. On at least one other television the old blanket request caused every server transcode to be refused outright before a single frame decoded; whether this release's version of the fix also clears that television has not been re-checked there — see "Help test this release".
- **BACK now hands the screen to the television at Home, and at the who's-watching picker or sign-in whenever there is nothing inside the app to go back to**, the way every other app on this platform does, instead of asking "Exit PlxNative?" first. Where BACK can resume something — an unprotected profile you were already using — it still does that, as before.
- **Sign-in no longer strands you on an expired QR code.** Plex's sign-in code lapses after 15 minutes; the screen used to just sit there with nothing to do about it, and now keeps minting fresh codes or tells you to press OK for a new one.
- **Auto no longer drops out of Original for no real reason right after starting or resuming playback**, when its buffer legitimately hadn't finished filling yet and was read as a struggling connection instead. A seek shortly after a quality switch no longer risks stalling the picture for the remainder of a transfer already in flight.
- **"Delete all local data" can now be scrolled fully into view** in Settings → Privacy & data — the last row in that list was clipped by a spacing bug shared by several other lists in the app, now fixed at its source.

## Compatibility

- **Plays video, verified by watching it — 2019 LG sets.** One television: an LG 49SM9000PLA, which reports platform release 4.10.2 (LG markets this generation as webOS 4.5).
- **Plays video, reported by someone else — one 2021 set.** [mariotaku](https://github.com/mariotaku) of webosbrew ran v0.2.1 on an LG 65UP7560AUD (platform release 6.5.2) on 2026-08-11 and got a picture: [issue #22](https://github.com/GLinnik21/plx-native/issues/22). Six of eight attempts played. That report has not been repeated on this version.
- **Starts, and nothing further is known — every other firmware from webOS 4.0 up.** The loader resolves this binary's libraries and symbols cleanly against every firmware image webosbrew has at 4.0 or newer. That grades startup and says nothing at all about whether video plays; the matrix is in the [technical audit](https://github.com/GLinnik21/plx-native/blob/main/docs/release-audits/v0.6.0.md).
- **Does not start — webOS 3.9.2 and older.** Symbols the app needs are missing from those firmwares, so the process is killed before anything appears.

If your set is in the middle two groups, [tell us what happened](https://github.com/GLinnik21/plx-native/issues). It working is as useful a report as it failing.

## Known issues

- **Auto has only been exercised in a laboratory** — one television, one server, and a link throttled on purpose. A link that degrades slowly, or a server already busy transcoding for somebody else, has not been observed anywhere.
- **Playback on webOS 5, 7, 8, 9 and 11 is unverified.** The app starts there and nobody has reported watching anything.
- **Servers behind Plex's relay, and servers that require an encrypted connection**, are reached but have not been watched end to end.

## Help test this release

**If you filed issue #63 or have seen "Playback failed" with no further explanation**, please try again on this release. If it still fails, the failure screen now carries a support footer with your television's model, board and webOS release plus a failure code — a photograph of it is the single most useful thing you can add to [the issue](https://github.com/GLinnik21/plx-native/issues/63).

**If your television is a 2024 LG set, or reports a platform release of 10.3.1 or newer**, please try playing a file that needs a server transcode (not a file your television can direct-play). An earlier, narrower version of this release's decode-request change was confirmed to fix a hard refusal on one such television in a test lab; the version that shipped here has not been re-checked on that hardware. Either outcome — it plays, or it still refuses — is useful, and a refusal is more useful with the failure screen's photograph attached.

**If your connection to your server is slow, congested or over Wi-Fi, try Auto and say what you saw.** [Open an issue](https://github.com/GLinnik21/plx-native/issues). It working is as useful a report as it failing.

## Installing

Download **com.beb.plxnative_0.6.0_arm.ipk** and install it with the [Homebrew Channel](https://github.com/webosbrew/webos-homebrew-channel) or [dev-manager-desktop](https://github.com/webosbrew/dev-manager-desktop). You do **not** need a rooted TV.

Nothing in this distribution chain is signed, so this sha256 is what tells you the file you have is the file published here:

```
__IPK_SHA256__  com.beb.plxnative_0.6.0_arm.ipk
```

[Installing and checking a download](https://github.com/GLinnik21/plx-native/blob/main/docs/install-and-verify.md) covers the other assets, how to check the hash on each platform, and the Developer Mode expiry that uninstalls your apps. This package bundles FFmpeg under LGPL-2.1-or-later and its complete corresponding source is attached to this release. Exactly what was built, verified and shipped is in the [technical audit for v0.6.0](https://github.com/GLinnik21/plx-native/blob/main/docs/release-audits/v0.6.0.md).
