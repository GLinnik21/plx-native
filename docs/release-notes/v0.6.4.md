# v0.6.4 — sign-in recovery and clearer diagnostics

This continues [issue #76](https://github.com/GLinnik21/plx-native/issues/76): 0.6.3 addressed one sign-in persistence path, while this release closes a code-proven unavailable-envelope path and adds a diagnostic read-out. No action required.

## Fixed

- **A fresh sign-in over a recognized secure envelope whose key service is unavailable now has an explicit recovery path.** The existing envelope is replaced at the candidate it was read from by the newly supplied sign-in in the owner-only format, so the result survives the next launch. The same fresh-reauth authority covers the separate client-ID-only plaintext shadow case: known lower copies are swept, while an unknown envelope remains protected by the never-overwrite rule. Whether real keymanager3 sets follow these code-proven paths remains unconfirmed.

## What's new

- **The sign-in screen can tell you why a sign-in was not kept.** A storage-details button on the sign-in screen opens a panel — meant to be photographed — with what your last save actually did (kept as a sealed file, kept as the plain file, left an existing protected file alone and why, or failed to write at all), which key service state was seen and which identity the app registered under, and, for each location on the television it looked for a saved sign-in, why the file there was not usable (missing, could not be opened, wrong owner, too large, or similar). BACK closes it. Nothing in the panel is a path, a token, or anything else that identifies you.
- **Details can send a diagnostic report even when QR polling works normally.** After confirmation, it includes the original startup read, key-service errors and identity categories, fresh-save results and per-location write errors, plus the app/webOS/hardware context. It exposes a Report ID you can quote. Reports normally use the on-disk queue; if the queue cannot be written, a bounded background send is attempted from memory. Acceptance is not a delivery guarantee, and the screen distinguishes queued, sending, sent and failed states.
- **A sign-in that could not be saved stays on a clear warning before continuing.** Open Details to send its diagnostics, or choose Continue to use the current session. Continuing does not repeat the failed save or require another QR authorization.

## Changed

- **Standing reporting choices are unchanged.** The notice now describes the richer diagnostics and fallback. Existing accepted Errors/Usage scopes do not trigger a new account-wide question; each one-off report still requires its own explicit confirmation.
- **Alert text is left-aligned and long titles wrap inside the panel.** The shared confirmation component measures the wrapped title for both drawing and button hit-testing.
- **The sign-in screen keeps technical information in Details.** The duplicate connection-error line and technical footer are removed; Details explains when sending a report is useful. Details and its report confirmation do not appear on top of each other.

## Compatibility

- **Starts and renders the sign-in UI, verified on the dev set — 2019 LG set.** An LG 49SM9000PLA reports platform release 4.10.2 (LG markets this generation as webOS 4.5). The current native session verified startup, the storage-details interactions and relaunch behavior at 1920×1080. This set has no `keymanager3`, and no media was played in this release verification.
- **Prior playback baseline — one 2021 set.** [mariotaku](https://github.com/mariotaku) of webosbrew ran v0.2.1 on an LG 65UP7560AUD (platform release 6.5.2) on 2026-08-11 and got a picture: [issue #22](https://github.com/GLinnik21/plx-native/issues/22). Six of eight attempts played. That is a prior-version report, not playback verification for v0.6.4.
- **Starts, and nothing further is known — every other firmware from webOS 4.0 up.** The loader resolves this binary's libraries and symbols cleanly against every firmware image webosbrew has at 4.0 or newer. That grades startup and says nothing at all about whether video plays; the matrix is in the [technical audit](https://github.com/GLinnik21/plx-native/blob/release/v0.6/docs/release-audits/v0.6.4.md).
- **Does not start — webOS 3.9.2 and older.** Symbols the app needs are missing from those firmwares, so the process is killed before anything appears.

Whether the fixed loop, and the storage-details panel's facts, look the same on a set with a real `keymanager3` remains unconfirmed; no current real-keymanager3 recovery run is claimed here.

## Known issues

- **Whether a real `keymanager3` reproduces the fixed loop, and recovers the same way, is unconfirmed.** The dev fake reproduced a matching symptom and host tests watched the defect fail before the fix landed; no television with a real key service was available to check the recovery against directly.
- Every other known issue in [v0.6.3's audit](https://github.com/GLinnik21/plx-native/blob/release/v0.6/docs/release-audits/v0.6.3.md#known-issues-at-release-with-provenance) not superseded above is unchanged, including the one-off libmali SIGSEGV recorded there.

## Help test this release

If you reported in [issue #76](https://github.com/GLinnik21/plx-native/issues/76): install this version, sign in once, and confirm the sign-in still stays put after the television has gone to standby and woken back up. If the QR/sign-in screen appears unexpectedly, open **Details → Send report** before retrying and confirm the report. Tell us its Report ID and the displayed delivery status. The report preserves startup facts separately from a later save; no SSH access or permanent reporting opt-in is required.

## Installing

Download **com.beb.plxnative_0.6.4_arm.ipk** and install it with the [Homebrew Channel](https://github.com/webosbrew/webos-homebrew-channel) or [dev-manager-desktop](https://github.com/webosbrew/dev-manager-desktop). You do **not** need a rooted TV.

Nothing in this distribution chain is signed, so this sha256 is what tells you the file you have is the file published here:

```
__IPK_SHA256__  com.beb.plxnative_0.6.4_arm.ipk
```

[Installing and checking a download](https://github.com/GLinnik21/plx-native/blob/v0.6.4/docs/install-and-verify.md) covers the other assets, how to check the hash on each platform, and the Developer Mode expiry that uninstalls your apps. This package bundles FFmpeg under LGPL-2.1-or-later and its complete corresponding source is attached to this release. Exactly what was built, verified and shipped is in the [technical audit for v0.6.4](https://github.com/GLinnik21/plx-native/blob/release/v0.6/docs/release-audits/v0.6.4.md).
