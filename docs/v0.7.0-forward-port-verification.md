## Semantic adapters and unresolved oracle gaps

Source and target adapters must translate the same scenario into the production coordinator/client
path and collect state, permitted action, persistence, side effects, and partial order; adapters
may not decide migration, durability, consent, or admission. This is required because v2 profiles
and owned Session/Consent/Player representations are accepted differences, while their semantic
outcomes are not. v2→0.6.6 downgrade is explicitly unsupported and is not a source-binary oracle.

Host tests cannot run ARM DB8, Keymanager, Starfish/ACB, or affected-chassis Repair: the thin
adapter boundary is host coordinator semantics → helper service/IPK/TV observation. The available
TV cannot prove newer-TV Keymanager, k5lp/k3lp Repair, or C stuck inside firmware; `holdload` is
only a positive semantic control. No target test, differential observation, mutation, ARM artifact,
sim inspection, package install, or TV observation has been recorded.

Approved corrections beyond the 0.6.6 source behavior:

- **DIFF-05:** the issued→return budget also covers a constructor that never reaches `sf_ready`.
  The v0.6.6 early return left that state in Connecting forever. A ready-object demux failure keeps
  its earlier precedence, and return→loadCompleted retains its own full budget.
